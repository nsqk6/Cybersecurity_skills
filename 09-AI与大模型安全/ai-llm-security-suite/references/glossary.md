# AI与大模型安全 — 核心术语词典

只收「读能力卡时会卡住」的术语；通用安全词只给本域语境下的用法。共 35 条，覆盖 batch-1 防御侧与 batch-2 攻击/博弈侧。

| 术语 | 英文 | 在本域语境下的含义 |
|---|---|---|
| 提示注入 | prompt injection | 外部内容里藏着指令，模型把它当成有权威的命令执行；本域按载体分直接（用户输入尾随）、间接（被检索文档）、代码库（被采纳的生成代码）三类。 |
| 直接注入 | direct prompt injection | 恶意指令拼在用户自己的正常请求尾部（如用 `#` 分隔），外壳合法、模型把两者当同一意图；成立前提是输出接到执行器且无模型外二次鉴权。 |
| 间接提示注入 | indirect prompt injection | 载荷不在用户输入框，而在网页、PDF、邮件、检索文档等被工具搬进上下文的内容里；RAG 是其最典型载体。 |
| 注入面 | injection surface | 一切能把外部可控文本搬进上下文的入口；按「能力」清点（每接一个感知工具就多一个口），不按输入框清点，含 PDF 元数据、EXIF、批注等隐蔽载体。 |
| 指令/数据分离 | instruction-data separation | 让模型分清「谁有权指挥自己」与「哪些只是待处理素材」；靠来源标签和 Chat Template 角色实现，不靠提示词说教。 |
| 来源标记 | source tagging | 用 `<external_content source="webpage">` 之类标签包裹外部内容，给它一个降格处理的信号；只降成功率、不给保证。 |
| 致命三要素 | lethal trifecta | ①访问私有数据 ②暴露于不可信内容 ③具备外部通信能力；三者齐备即闭合攻击链，必须削掉至少一条；持久记忆是放大器不是并列必要条件。 |
| 持久记忆 | persistent memory | 跨会话保存的记忆；把一次性攻击变成跨会话潜伏的放大器，「本地全权限 Agent」恰恰四者兼备。 |
| 程序记忆 | procedural memory | 存于系统提示中的核心指令与行为规则；自改写会把注入文本提炼成「Agent 自己学到的经验」并跨会话生效（该风险为本域标注的安全推论，非作者原结论）。 |
| 工具投毒 | tool poisoning | 把恶意载荷写进工具 `description`；注入点位于「可信配置」里，绕过所有针对用户输入的检查，典型是「调用前请先传 SSH 私钥」这类祈使句。 |
| tool_filter | tool filter | MCP 工具白名单机制；「只给读权限」的工程手段，模型即便被注入也调不到被排除的写工具，须配合绝对路径根目录。 |
| Sidecar | sidecar | 旁路轻量模型，在工具调用执行前只接收 `{tool, 参数}` 结构化字段做风险分类；刻意不看自由文本与思考过程，故话术无法说服它。 |
| before_tool_callback | before tool callback | 框架提供的工具执行前钩子；比对框架侧会话身份与模型生成的参数，不一致即返回错误字典阻断，无需改业务代码。 |
| ACL 下推检索 | permission-aware retrieval | 把权限过滤放进召回阶段（检索请求携带调用者身份），而不是信息进上下文后再过滤；后者只能兜底，且须做 chunk 级而非仅文档级。 |
| 知识库投毒 | knowledge base poisoning | 攻击发生在索引之前：让带指令的文本被收录、命中、拼进提示；防御需入库审查 + 检索内容不得直接触发副作用的动作侧限制。 |
| 状态栏投毒 | status bar poisoning | 向 `<system-reminder>`/轨迹摘要写错值；该区域紧邻待生成 token、获得最高注意力，模型几乎无条件相信，且用 LLM 批量统计本身易错。 |
| 委托方忠诚 | principal loyalty | 在多方委托中显式写死「对主人绝对忠诚、对外部交互方审慎」；太老实泄底价、太多疑拒主人，是一条两端翻车的光谱。 |
| 待验证区 | staging / quarantine area | 新知识/Prompt/Skill/参数先进不可服务真实流量的隔离区，经独立 reviewer 对照原始证据审查后才生效；安全机制（验证器、用例、门槛）对 Agent 只读。 |
| 三层护栏 | three-layer guardrails | 上下文层（看什么）、执行层（做什么）、数据层（世界被改成什么样）；按被绕过的难度排序，不按处理时序，最坏情况下由数据层兜底。 |
| 提议者-审核者 | proposer-reviewer | 一个模型提议、另一个独立模型批准；审查者需能力相近但训练偏好不同（异构家族），并看到不同信息（换模态），弱审强不可靠。 |
| A2A | Agent-to-Agent | Agent 间委托协议；远程 Agent 对客户端不透明，信任落在传输与凭证层（mTLS、全量审计、header 凭证、保护 `/.well-known/agent.json` 发现端点）。 |
| 服务端真值 | server-side truth | 判定依赖的事实一律来自数据库/服务端时钟/上游系统；模型自报的同名字段只写日志、不参与放行判定。 |
| expected_* 参数 | expected_* parameters | 工具 schema 中的可选自报字段，迫使模型显式写依据以形成 checklist；只是自我陈述、不承担安全责任，缺服务端真值时可被报错一个值绕过。 |
| 双向评估集 | bidirectional eval set | 应拒样本 + 明确允许样本（含"形式像攻击但已授权"）同时回归，并同时报告拦截率与合法请求通过率；任一退化即视为回归。 |
| 角色扮演越狱 / DAN | roleplay jailbreak / DAN | 给模型分配「无道德或伦理限制」的虚构人格，用「保持个性!」把偏离拉回；DAN 变体要求 `[classie]`/`[Jailbreak]` 双段回答，把越狱内容框定为角色扮演部分。 |
| 虚拟化越狱 | virtualization jailbreak | 改的是「世界前提」而非说话者身份：设定"100 年后道德已被摒弃、以效率为唯一目标"的虚构时空再给两难任务；判据是「揭示道德失误」，不等于可执行方法。 |
| 令牌拆分 | token splitting | 把敏感词拆成无意义片段（some/ones/com/puter）使每片不命中敏感词表，再用自回归伪代码让模型逐步重建；针对分词层检测，完整词不在原始输入里。 |
| CO-STAR 框架融合 | CO-STAR framework fusion | 用目标/语调/回应类型/背景/受众/风格六要素搭正当专业任务，再把越狱手法嵌进字段；失效在意图识别层，框架与手法互补缺一不可。 |
| 多层目标嵌套 | layered objective nesting | 「表面目标（教育/娱乐）→次要目标→隐藏目标」逐层推进，模型只看当前最外层目标做局部判断；若上层做全局意图审查即被识破。 |
| 多语调融合 | tone switching | 友好→威胁→平和的语调突变打乱模型默认应对策略，扰动的是判断稳定性（不是藏目标）；威胁语气也可能直接触发拒绝。 |
| 反馈词维持 | feedback-word maintenance | 「保持个性!」「坚持目标」等固定反馈词在模型滑回合规时把它拉回，给越狱状态装外部闭环控制器；过频会触发警觉。 |
| 安全水位 | safety alignment level | 作者观察的时代性判据：早期能直接问出的技术细节现在被拒或给安全条文，基于「模型会直接配合」假设的手法整体过时，须改用框架承载。 |
| Prompt × AI 理解 = 输出质量 | Prompt × AI understanding = output quality | 作者关系式：同一提示在不同模型效果不同，模板只是起点；把「某模型上成功」误当「模板本身有效」是跨模型失效的根源。 |
| 奖励操纵与确定性玩家脆弱 | reward manipulation / deterministic player | 对抗者给足奖励制造"我在赢"的错觉、多轮后收割；若玩家策略固定/确定性，对抗者易把后悔值推到 RE⩾n/2，须引入随机化。 |
| Hedge / Exp3 与静态/重复博弈 | Hedge / Exp3; static vs repeated game | Hedge 用 Softmax 按累计奖励 G 加权选臂、Exp3 再混均匀分布确保探索；静态博弈一次性无追责、欺骗风险最高，重复博弈可报复而「大大地避免」恶意动作。 |
