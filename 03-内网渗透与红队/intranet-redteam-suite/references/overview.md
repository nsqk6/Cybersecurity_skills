# 内网渗透与红队 — 域总览

## 这个域解决什么问题

这里处理的不是「某个漏洞怎么打」，而是**拿到一个立足点之后，怎么规划到目标资产的路径、怎么在不暴露自己的前提下取凭据、横向、维持权限**。本域 12 个能力按「侦察 → 入口 → 凭据 → 提权 → 横向 → 维持 → 规避 → C2」组织。

## 能力地图

| 二级分类 | 能力 | 一句话规则 |
|---|---|---|
| 工具链 | `c2-tunnel-infrastructure` · C2 出网通道与隧道基础设施 | 这个能力解决的是「打进去了、但会话不上线」这一类最消耗时间的问题 |
| 利用与提权 | `credential-extraction` · 凭据取用：从配置、内存到目录复制 | 这个能力解决的是「拿到一台机器后，怎么把凭据从『存在但看不见』变成『可复用的认证材料』」，以及一个更重要的判断： 我拿到的这个值，到底能用来干什么 |
| 侦察 | `domain-recon-path` · 域内侦察与突破路径定位 | 这个能力解决的是「刚打进内网、只有一两台机器时，用什么顺序把『值不值得冒险』问清楚」 |
| 权限维持 | `endpoint-persistence` · 端点持久化与入口冗余 | 这个能力解决的是「怎么保证明天还能进来」，但它真正的判断点不在「用什么手法」，而在 先分清要维持的是哪一种「在」 |
| 免杀与规避 | `evasion-and-opsec` · 载荷免杀与行动 OPSEC | 这个能力解决的是「怎么让对手看不见我」，但它不是一种技术，而是 三层互不替代的隐蔽 |
| 侦察 | `external-recon-pretext` · 外部情报与社工接近设计 | 这个能力解决的是「面对一个几乎一无所知的组织，怎么在不动手之前就把入口想清楚」：包括查什么、查到的东西算不算数、最后用什么身份站到对方面前 |
| 利用与提权 | `initial-access-delivery` · 外部打点：投递、接口面与多因素绕过 | 这个能力解决的是「外部第一个口子从哪来」，以及更关键的： 当最直接的那条投递路径被静默拦掉时，怎么判断被拦、往哪降级 |
| 横向移动 | `kerberos-ticket-abuse` · Kerberos 票据伪造与委派滥用 | 这个能力解决的是「拿到某类 hash 之后，怎么把它变成一张能用来访问资源的票」，以及在三条路（借合法机制、伪造票、跨信任越界）之间怎么选 |
| 横向移动 | `lateral-execution-channels` · 横向执行通道选择 | 这个能力解决的是「手上有了管理员口令或 hash、目标机器就在那里，我用什么方式把命令送过去」 |
| 横向移动 | `ntlm-relay-coercion` · NTLM 带外窃取与中继 | 这个能力解决的是「不破解、不猜口令，直接借用别人的一次认证过程来拿权限」 |
| 利用与提权 | `password-attack-reuse` · 口令攻击与复用滚雪球 | 这个能力解决的是「在没有漏洞可打的情况下，怎么靠口令本身把权限面扩开」，核心是三件事： 节奏、规则、复用 |
| 利用与提权 | `windows-db-privesc` · Windows 与数据库提权路径 | 这个能力解决的是「拿到一个普通用户 shell（或一个只有 db_owner 的数据库账号）之后，怎么在十分钟内找对提权路径，而不是挨个试 EXP」 |

## 域的共性失败模式

（下列条目逐条摘自各能力卡 B 段，均为语料中作者明确写出的坑）

- **c2-tunnel-infrastructure**：**不做协议探测就直接投 HTTP beacon**：长时间不上线后被误判为「木马不免杀」或「目标不可达」，把时间浪费在免杀上。
- **credential-extraction**：**改了 WDigest 不重新登录**：内存里仍是旧状态，误判「改了也没用」（《红蓝对抗之Windows内网渗透》4.2 明确要求锁屏/注销/重启）。
- **domain-recon-path**：**上来就抓密码或全端口扫描**：《红蓝对抗之Windows内网渗透》开篇明写会触发 IDS 告警并丢失权限。作者在 Shiro 案例中自评全段扫 MS17-010「动作其实有些大」。
- **endpoint-persistence**：**只留内存会话**：目标重启或 C2 被封即永久失去入口（09 的原始教训）。
- **evasion-and-opsec**：**只做单层**：改 shellcode 加花指令仍会被启发式标记（第 7 章原话）。
- **external-recon-pretext**：**只答完 11 问就动手**：《The Art of Attack》第 5 章明说这 11 问「aren't magic」「may not be the right questions for your target」，不生成第二轮等于没做深度。
- **initial-access-delivery**：**把「发送成功」当「投递成功」**：111 中第一批 exe 附件全部被网关拦截，发送端无报错，等于白做。
- **kerberos-ticket-abuse**：**用 IP 访问**：票据绑定服务主体名，用 IP 必然拒绝访问（多份材料都把它列为第一坑）。
