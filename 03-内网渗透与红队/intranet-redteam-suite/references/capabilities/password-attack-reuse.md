## I — 方法论骨架 (Interpretation)

这个能力解决的是「在没有漏洞可打的情况下，怎么靠口令本身把权限面扩开」，核心是三件事：**节奏、规则、复用**。

**节奏（喷洒）**。账户锁定按「同一账户在观测窗口内的失败次数」计数。喷洒把失败分散到多个账户，每个账户每轮只失败 1 次；再用 ≥ 锁定观测窗口的间隔，使任意窗口内的单账户失败数始终不达阈值。前提是**先读密码策略**（锁定阈值 + 观测窗口），否则间隔是拍脑袋。作者给出的下限是 30 分钟，实际应取「观测窗口 + 余量」。命中一个即停，转入该账户的权限评估，不继续扫——继续扫只会把已成功的账户也推向锁定。

**规则（按主机属性生成）**。批量装机常用「固定前缀 + 与主机属性绑定的后缀」，于是密码成为 IP 的函数。两个样本足以提出假设（如后两位 = IP 第三四段之和），但两点之间总能画出一条直线——**必须用第三个样本证伪后才能推广**。这条链路的信息价值不在公式本身，而在「样本 → 假设 → 验证 → 批量」这个顺序；缺了验证一步，就会在一条错误规则上跑完整段。

**复用（滚雪球）**。内网资产多为批量部署/克隆，同一口令被复用到几十上百台是常态；而挖一个新漏洞的成本远高于复用一次已验证的凭据。于是最优路径是正反馈：每拿到一台新主机就抓凭据 → 用新凭据重跑同网段的 SMB/RDP/SSH/数据库 → 新机器再产出新凭据。攻击面从「漏洞」转移到「凭据图」，速度取决于撞库速率而非漏洞挖掘能力。收敛判据是「新增可访问主机数趋零」。

三条原则的共同前提是**控制速率**：高线程撞库会触发锁定或告警（同一批文章里出现过「多按了几次回车，连接次数过多，IP 被锁定了」，直接断掉整条路）；挤掉正在登录的运维会话会引起人工排查。所以撞库的正确形态是低线程、分时段、按网段小批推进，先小样本复核再扩大。

还有一条经常被忽略的排序：**当手上已经有一组可用口令时，先横向滚一轮，再回去挖漏洞**。理由不是「漏洞没用」，而是「已验证凭据的边际收益远高于新漏洞的期望收益」，而行动窗口是有限的。

## A1 — 应用示例 (Application Example)

### 示例 1: 从两台主机的密码样本推出全网规则
- **类型与来源**: 【亲历】163 酒仙桥六号部队《红队实战攻击之随缘测站（下）》
- **问题/输入**: 已控制两台同网段主机，各自拿到明文口令：IP 尾段 .12.19 对应 `fsads24#!f31`，.12.76 对应 `fsads24#!f88`。
- **方法论的使用**: 逐位对齐，识别出前 10 位恒定、后两位变化；对变化段提出可计算假设——后两位 = IP 第三段 + 第四段（12+19=31，12+76=88）；任取第三台同网段主机按假设生成口令实测，成功后才用该规则批量生成字典；跨网段前再做一次小样本复核。
- **结论**: 两点只能提出假设，第三点是证伪点；「先验证再批量」是本条方法的核心，而不是那个加法公式。
- **结果**: 原书交代第三台验证通过，之后跨网段套用成功。

### 示例 2: Summer2018! 单点命中
- **类型与来源**: 【例题】《渗透测试实战（第三版·红队版）》第 9 章 10 码线
- **问题/输入**: 已通过 OSINT 与邮箱规则收集到一批用户名，需要在不知锁定策略的前提下试口令。
- **方法论的使用**: 先用 `net accounts /domain` 或 `cme smb <dc> -u x -p x --pass-pol` 读出锁定阈值与观测窗口；构造 1–3 个高概率密码（公司名+年份、季节+年份、当地球队编号、历史泄露库同公司样本）；每轮对每个账户只试 1 个密码，用 `--no-bruteforce` 只测 user=password 的情形；轮间隔 ≥ 观测窗口；命中即停。
- **结论**: 高概率候选（`Summer2018!` 属于季节+年份+符号）配合「一密多号」，能在不触发锁定的前提下命中。
- **结果**: 原书交代命中 Chris Catfield 账户，随后转入该账户的权限评估。

### 示例 3: 一个口令滚出 68 台
- **类型与来源**: 【亲历】163 酒仙桥六号部队《蝴蝶效应翻起的内网漫游巨浪》
- **问题/输入**: 拿到一组 Linux root 口令。
- **方法论的使用**: 用该凭据对同网段跑 SMB/RDP/SSH/1433 的低线程撞库 → 每进一台新机立即抓凭据（配置文件、history、SSH 相关文件；Windows 侧用 wce / 星号密码查看器）→ 新凭据并进字典 → 重复直到新增主机数趋零。
- **结论**: 复用的收益随机器数量指数上升，因为每台新机都可能带来一组新凭据。
- **结果**: 原书交代 61 台 Linux + 7 台 Windows，作者称「一个密码几乎打下这个网段的机器」。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要它
1. 手上有一批用户名但没有口令，需要在不知锁定策略下试探。
2. 发现多台主机密码「看起来有规律」，需要判断能否外推。
3. 已有几组凭据，需要决定「继续挖漏洞还是先横向滚一轮」。
4. 撞库过程中出现账户锁定或被封 IP，需要判断是节奏问题还是策略没读。
5. 需要评估「这批资产的口令强度」作为一项测试结论。

### 语言信号（出现这些就该激活）
- 中文：「密码喷洒」「怎么爆破不锁定」「密码好像有规律」「内网口令规律」「一个密码打穿内网」「口令复用横向」「撞库被封了」
- English: "password spraying without lockout", "password pattern based on IP", "same password rule across subnet", "credential reuse across subnet", "same local admin password"

### 与相邻能力的区分
- 与 `credential-extraction` 的区别：那张卡产出认证材料（hash/明文/票据材料）并判定形态；本卡只用「已经可用的材料」，管的是用它的节奏与范围。
- 与 `domain-recon-path` 的区别：那张卡给「打哪台」，本卡给「用什么口令打、打多快」。
- 与 `lateral-execution-channels` 的区别：本卡只管「凭据是否有效」，通道协议选择在那张卡。

## E — 可执行步骤 (Execution)

**必需输入**: ①用户名清单（OSINT / kerbrute userenum / LDAP 枚举）；②至少一组候选口令或口令生成规则；③域/主机密码策略（锁定阈值 + 观测窗口）——**缺 ③ 必须先取**，否则不得开始；④撞库目标清单与可达性。缺 ③ 时唯一允许的动作是读策略。
**交付物与完成标准**: 一份「口令攻击台账」：每轮记录候选口令、目标账户数、尝试时间窗、命中结果、锁定/告警迹象；另附「命中账户 → 可访问目标」的验证结果。完成标准是能回答「这批账户的口令强度」或「拿到了几个可用账户」，且全程无账户被锁死。

1. **读策略（强制前置）**
   - 做什么：`net accounts /domain` 或 `cme smb <dc> -u x -p x --pass-pol`；记录锁定阈值、观测窗口、是否启用锁定。
   - 完成标准：拿到具体数字（例如「5 次 / 30 分钟」）。
   - 判停：若拿不到策略，按最保守假设（阈值 3、窗口 60 分钟）执行，或直接放弃喷洒转 `credential-extraction`（配置层取材风险更低）。

2. **选形态：喷洒 / 规则生成 / 直接复用**
   - 做什么：只有用户名 → 喷洒；已有多台主机的明文口令 → 先试规则反推；已有可用凭据 → 直接复用滚雪球。
   - 完成标准：明确本轮属于哪一形态，并写下对应的速率上限。
   - 判停：若手上有 ≥2 组同网段主机的明文口令，优先做第 4 步（规则反推）而不是喷洒——规则命中的收益远高于盲猜。

3. **构造候选口令（≤3 个/轮）**
   - 做什么：公司名+年份、季节+年份、产品名+数字、当地球队/地名编号、历史泄露库里同公司样本；每个候选都要写「为什么它概率高」。
   - 完成标准：候选数 ≤3，且每个都有构造理由。
   - 判停：若候选超过 3 个，砍掉理由最弱的——多一个候选就多一轮暴露窗口。

4. **规则反推（有样本时）**
   - 做什么：把 ≥2 台主机的明文口令与各自 IP 并排记录；逐位对齐找恒定段与变化段；对变化段提出可计算假设；任取第三台同网段主机实测。
   - 完成标准：第三台验证成功；若失败，说明假设错，回到对齐步骤而不是换公式硬套。
   - 判停：只有一台样本时不得外推（无法区分「规律」与「巧合」）；跨网段套用前必须再做一次小样本复核。

5. **执行第一轮（一密多号）**
   - 做什么：每轮对每个账户只试 1 个密码；`--no-bruteforce` 只测 user=password；控制并发（低线程），避开业务高峰与值班时段。
   - 完成标准：本轮结束时有明确的「命中账户列表」与「失败账户列表」，且没有任何账户达到锁定阈值。
   - 判停：若出现任一账户被锁或被封 IP，立即停手，把该账户加入排除表，并把间隔加倍后再继续。

6. **轮间隔 ≥ 观测窗口（+余量）**
   - 做什么：两轮之间至少间隔锁定观测窗口（作者下限 30 分钟），宁可慢；把每轮的起止时间记下来以便证明「任意窗口内单账户失败数 < 阈值」。
   - 完成标准：时间账能对上，不靠记忆。
   - 判停：若无法保证间隔（例如多人在跑同一批账户），停止并改为按账户分片，避免叠加失败。

7. **命中即停，转权限评估**
   - 做什么：命中一个账户就停下，用该账户验证「能访问什么」（SMB/WinRM/RDP/数据库/邮件/内网系统），把结果写进台账。
   - 完成标准：命中账户的可访问面已确认。
   - 判停：若该账户无任何可访问面（如只有邮箱），不要继续用它做撞库源，回到第 5 步换候选。

8. **滚雪球并收敛**
   - 做什么：每进一台新机立即取材（配置层优先，见 `credential-extraction`），把新凭据并进字典；对同网段重跑；遇到不同系统换对应抓取方式。
   - 完成标准：新增可访问主机数趋零，或达到 objective。
   - 判停：若某网段连续两轮无新增，判定该网段口令已收敛，转下一网段或停止；不要在同一网段反复撞已失败的账户。

## B — 边界 (Boundary) ★

### 不要用的情况
- 目标启用了智能锁定（如 AD 的「账户锁定阈值 + 计数器重置时间」配合动态风控）或第三方 UEBA：分散失败仍会被「跨账户、同源、同时间窗」的模式识别抓到，喷洒的低噪声假设不成立。
- 目标是高管/特权账户且策略未知：一次锁定就可能触发人工介入，代价远高于收益。
- 已有配置层明文可拿（SYSVOL、conn.asp、FTP 客户端）：此时喷洒是「用高噪声手段拿低价值结果」，应先翻配置。
- 需要长期隐蔽：任何形式的在线认证尝试都会在 DC 上留 4625，量大即是信号。

### 已知失败模式
- **不看策略就喷洒**：可能锁死域管账户，直接打草惊蛇（《渗透测试实战》明确警告「失败过多可能会被封禁」）。
- **同一密码对全部账户并发尝试**：短时间内形成明显模式，等于自报。
- **只凭单台样本外推规则**：无法区分「规律」与「巧合」；107 的作者也是「又随便找了台同网段的试了一下」才敢推。
- **跨网段直接套用规则不复核**：不同批次的装机镜像可能用不同规则。
- **命中后不停手**：继续扫会把已成功账户也推向锁定，且延长暴露窗口。
- **高线程撞库**：096 中「多按了几次回车，连接次数过多，IP 被锁定了」，整条路断掉。
- **挤掉在线运维会话**：RDP/交互式登录会踢掉正在使用的人，引发人工排查。
- **把「无命中」当「口令强」**：也可能是候选质量差、账户不存在、或该网段不在同一口令体系内。

### 作者与时代的局限
- 案例环境多为 2018–2021 年的国内企业，口令习惯集中在「公司名/季节 + 年份 + 符号」。当前多数企业已强制 12 位以上 + MFA，单靠喷洒拿到可用会话的概率显著下降。
- 「密码 = IP 的函数」这类规则依赖手工批量装机；现在镜像化部署 + LAPS + 随机初始口令已让该模式大幅减少，规则反推的适用面在收窄。
- 书中未讨论「在线喷洒被条件访问（Conditional Access）拦在第二因素」的情况：即使口令正确，没有 MFA 也无法形成会话，此时应转 `initial-access-delivery` 的 MFA 绕过面。
- 未讨论云身份（Entra ID / Okta）的喷洒：云侧的锁定策略、IP 信誉、异常登录检测与本地 AD 完全不同，节奏参数不可直接迁移。

### 容易混淆的方法
- **喷洒 vs 爆破**：爆破是「多密一号」，喷洒是「一密多号」；前者必然触发锁定，后者靠分散规避。
- **规则生成 vs 复用**：规则生成产出「每台不同但可按公式算」的口令；复用是「同一串口令复制到多台」。两者常同时使用，但验证方式不同（前者必须第三点证伪）。
- **口令攻击 vs 凭据抓取**：前者靠猜/算，会在 DC 留 4625；后者靠读，留的是进程与文件访问痕迹。
- **撞库 vs 密码复用检测**：前者是攻击动作，后者是防守侧的横向移动检测点（同一账户短时间内在多台主机认证）。
