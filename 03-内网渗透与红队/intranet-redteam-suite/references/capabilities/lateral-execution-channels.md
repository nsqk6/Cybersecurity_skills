## I — 方法论骨架 (Interpretation)

这个能力解决的是「手上有了管理员口令或 hash、目标机器就在那里，我用什么方式把命令送过去」。核心不是一个工具清单，而是三个正交的判断。

**第一判：要不要会话。** 横向手段分两类，混用会付不必要的代价：

- **只执行**（WMI / atexec / schtasks / sc / WinRM 的单命令模式）：不落文件、不建服务，适合「跑一条命令取结果」。
- **派生会话**（psexec / smbexec / DCOM + payload）：需要落地物或新进程，适合「要一个稳定据点」。

判断依据是 objective：只要一条命令的输出（读一个文件、查一次配置、跑一次 whoami），就不要派生会话——多一个会话就多一个需要维持和清理的对象。反之，如果你要在这台机器上反复作业，只执行模式会让你每次都重新认证，噪声反而更高。

**第二判：前置服务成不成立。** 四种通道本质是四组前置条件：

| 通道 | 前置条件 | 落地物 | 典型痕迹 |
|---|---|---|---|
| IPC$ + 计划任务 | 139/445 可达，未禁空连接/共享；`at`（≤2008）或 `schtasks`（2012+） | 视命令而定 | 任务创建事件、任务 XML |
| WMI | 135 可达 + WMI 服务；`wmic` 无回显 | 不落文件 | WMI 活动日志、进程创建 |
| PsExec | ADMIN$ 可写 + 能创建服务 | `PSEXESVC.EXE` | 服务创建（7045/7036）、服务文件落地 |
| WinRM | 5985/5986（2012+ 默认开） | 不落文件（走 PowerShell 会话） | WinRM 日志、PowerShell 日志 |

选通道不是选顺手的工具，而是看目标上哪组前置条件成立；同一台机器上还要按系统版本换执行原语（`at` → `schtasks` → `sc`）。

**第三判：认证为什么失败。** 一个高频误判是「共享是开的、账号在管理员组，但 ADMIN$ 拒绝访问」。这不是共享权限问题，也不是「拒绝从网络访问」策略问题，而是 **UAC 的 remote restrictions**：本地管理员账号从网络登录时，令牌被过滤成标准用户。表现为 SMB 认证已通过、写权限拿不到。处置是关掉 remote UAC 或设 `LocalAccountTokenFilterPolicy=1`。判据很硬：**凭据错误会在 SMB 认证阶段就失败；认证通过但写入被拒，就是令牌完整性问题。**

还有一条贯穿全卡的纪律：**每一次横向都是一次配置变更**。开 3389、关防火墙、加管理员账号、创建服务，都是目标上「基线比对能看出来」的差异，而且安全设备对「服务器突然开 3389 / 防火墙被关」的告警优先级远高于对一次 webshell 访问。所以能不用图形通道就不用；需要传文件时优先用已有 C2/会话的 upload/download，不要在目标上开新服务。

## A1 — 应用示例 (Application Example)

### 示例 1: 四种通道在同一对跳板机/靶机上的对照
- **类型与来源**: 【亲历】163 酒仙桥六号部队《内网横向移动学习备忘录》· 02–05
- **问题/输入**: 已控 Win7 跳板机，拿到 Server 2012 靶机的管理员口令，需要在其上执行命令。
- **方法论的使用**: ① `net use \\target /user:administrator "pass"` + `net view` + `dir \\target\C$` 验证 IPC$ 与共享可写；② 需要无文件落地时改用 WMI：生成 Scripted Web Delivery payload，`wmic /node:... process call create "powershell ..."`（目标不出网则先把 payload 放跳板机的 SimpleHTTPServer）；③ 需要交互式回显用 PsExec；④ 2012+ 且 5985 开放时用 WinRM，先 `winrm enumerate winrm/config/listener` 确认；⑤ 计划任务按版本选 `at`（≤2003/2008）或 `schtasks /create /s ... /ru SYSTEM`。
- **结论**: 四种通道的前置条件互不相同，同一台靶机上「哪条能通」由端口与服务决定，不由工具偏好决定。
- **结果**: 原书逐条复现成功，并记录了失败面：2012 上用 `at` 直接失败；`wmic` 无回显容易被误判为执行失败（需 wmiexec.vbs 一类带回显的实现）；`schtasks` 建的任务若用户未登录可能不执行；psexec 传参加引号会报「系统找不到指定的文件」。

### 示例 2: PsExec 拒绝访问 → 其实是 remote UAC
- **类型与来源**: 【亲历】163 酒仙桥六号部队《浅谈 PSEXEC 做的那些事》
- **问题/输入**: 已知目标本地管理员账号，`net share` 能看到 ADMIN$、IPC$，但 `dir \\target\ADMIN$` 拒绝访问。
- **方法论的使用**: 先排除共享权限与「拒绝从网络访问这台计算机」策略（作者已排除），再转向 UAC 的远程限制；关闭目标 UAC 远程限制，或注册表 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\System` 下新增 DWORD `LocalAccountTokenFilterPolicy=1`；重跑 psexec。
- **结论**: 认证成功但写入失败 = 令牌被过滤，不是权限配置错误。判据是「失败发生在哪个阶段」。
- **结果**: 原书交代关掉 remote UAC 后 psexec 立刻成功；同时指出 psexec 必然留下 `PSEXESVC` 服务、7045/7036 事件与 `C:\Windows\PSEXESVC.EXE`（正常退出会删除）。

### 示例 3: 反例——为传文件开 3389、连不上就关防火墙
- **类型与来源**: 【亲历】163 酒仙桥六号部队《一次 Shiro 反序列化引起的域控沦陷》· 2. 内网渗透；《内网渗透从敲门到入门》· 拿 web 服务器
- **问题/输入**: 已拿到管理员 shell，需要把工具传到目标上。
- **方法论的使用**: 作者的第一反应是改注册表开 3389、加管理员账号、直连远程桌面；连接失败后判断是防火墙/白名单，改配置仍不通，最终放弃。事后自评「事后想想其实这一步实属弯路，不说实际利用价值，连接远程桌面就是一种暴露自己的行为」，并给出正解：「难道直接上线 CS 他不香吗」——用 C2 的 upload/download 传文件。
- **结论**: RDP 是「人」的通道，带来图形界面与拖拽便利，同时带来 4624 类型 10 登录事件、会话记录与必须开放的新端口。收益完全可以用已有会话替代。
- **结果**: 原书交代该步失败且被判定为弯路；同批文章另一次开 3389 被防火墙拦，作者明确「建议使用命令配置防火墙策略允许 3389 端口放行」而不是 `netsh advfirewall set allprofiles state off`。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要它
1. 有管理员凭据，需要决定用 WMI / PsExec / WinRM / 计划任务中的哪一个。
2. 只需要跑一条命令，不确定该不该派生会话。
3. PsExec 报「拒绝访问」但共享明明是开的，需要定位原因。
4. 需要传到目标机器一个工具，犹豫是否开 RDP/共享/新端口。
5. 445 不通或被强签名限制，需要找替代协议。

### 语言信号（出现这些就该激活）
- 中文：「PsExec 还是 WMI」「怎么横向到这台机器」「445 不通还能怎么打」「横向移动用什么」「psexec 拒绝访问」「admin$ 进不去但共享是开的」「远程桌面连不上」「怎么给服务器开 3389」
- English: "lateral movement without psexec", "winrm lateral movement", "psexec access denied remote uac", "wmi exec no output", "should I enable RDP on target"

### 与相邻能力的区分
- 与 `ntlm-relay-coercion` 的区别：本卡需要**已知凭据或 hash**；中继不需要知道密码，只需要有人来认证。
- 与 `c2-tunnel-infrastructure` 的区别：本卡是「命令投递方式」（OS 层执行原语），那张卡是「流量怎么回去」（网络层通道）。
- 与 `domain-recon-path` 的区别：那张卡产出「打哪台」，本卡产出「用什么协议打」。
- 与 `password-attack-reuse` 的区别：那张卡解决「凭据从哪来」，本卡解决「有凭据后怎么用」。

## E — 可执行步骤 (Execution)

**必需输入**: ①目标主机标识与可达性（哪些端口通）；②凭据形态（明文 / NTLM hash / 票据）；③objective（取一条命令输出 / 要一个稳定会话）；④目标系统版本（决定 `at` vs `schtasks`）。缺 ③ 必须先问，因为它直接决定「只执行」还是「派生会话」。
**交付物与完成标准**: 一份「通道选择记录」：选定通道、前置条件验证结果、执行证据（命令回显/会话 ID）、产生的痕迹清单（服务、文件、事件 ID）、清理动作。完成标准是拿到目标能力且痕迹清单完整。

1. **测可达性与前置条件**
   - 做什么：`nmap -p 135,139,445,5985,5986 <target>`；`net use \\target /user:<u> "<p>"` 验证 IPC$；`dir \\target\C$` 与 `dir \\target\ADMIN$` 分别验证读写；`winrm enumerate winrm/config/listener` 验证 WinRM。
   - 完成标准：得到「哪些通道前置条件成立」的表。
   - 判停：若全部不通，转 `c2-tunnel-infrastructure` 先解决可达性（代理/隧道），不要在本卡硬试。

2. **判「要不要会话」**
   - 做什么：写下 objective。只要一条输出 → 只执行（WMI/atexec/schtasks/sc/WinRM 单命令）；要反复作业 → 派生会话（psexec/smbexec/DCOM+payload）。
   - 完成标准：一句话能说清「选它的理由」。
   - 判停：若 objective 是「传一个文件」，两者都不选，改用已有会话的 upload/download。

3. **按前置条件选原语（含版本适配）**
   - 做什么：445 通 + 无强签名 → psexec/smbexec；445 受限 → DCOM 借宿主进程 或 WinRM(5985)；要无落地 → WMI（配带回显的实现）；计划任务按版本选 `at`（≤2003/2008）或 `schtasks /create /s ... /ru SYSTEM`。
   - 完成标准：选定的原语与前置条件表一致，且版本适配正确。
   - 判停：若目标 2012+ 而计划用 `at`，立即改为 `schtasks`（`at` 已弃用会直接失败）。

4. **处理认证层失败（remote UAC）**
   - 做什么：区分失败阶段——SMB 认证阶段失败 = 凭据错；认证通过但写 ADMIN$ 被拒 = 令牌过滤。后者关 remote UAC 或设 `LocalAccountTokenFilterPolicy=1`，重试。
   - 完成标准：能写 `ADMIN$` 或成功创建服务。
   - 判停：若已被「拒绝从网络访问」策略拦住，本卡通道全部失效，改走 WinRM 或已有会话。

5. **执行并留证**
   - 做什么：执行目标命令；立即记录回显/会话 ID；记录产生的痕迹（服务名、落地文件路径、任务名、事件 ID 7045/7036/4624）。
   - 完成标准：证据与痕迹都能对应到具体动作。
   - 判停：若 `wmic` 无回显，改用带回显的实现（wmiexec.vbs 类）确认执行结果，不要把「无回显」当「未执行」。

6. **评估噪声并决定是否继续用这条通道**
   - 做什么：对照痕迹清单判断「这条通道在这台机器上会不会被立刻抓」。有 EDR 的环境里 psexec 的服务创建 + 二进制落地是高置信告警；smbexec 的 C++ 版已被主流杀软查杀。
   - 完成标准：写下「本通道的暴露代价」，以及是否需要换通道。
   - 判停：若通道暴露代价高于本次收益，回第 3 步换原语，或转 `evasion-and-opsec` 先处理检测面。

7. **清理**
   - 做什么：删服务（`sc delete`）、删落地文件、删计划任务；确认 `PSEXESVC` 已退出（正常退出会自删，异常不会）。
   - 完成标准：目标上不残留本次动作创建的对象。
   - 判停：若清理动作本身产生更多事件（删除服务触发 7040），记录该权衡；在「痕迹已产生」的前提下，清理的收益是减少后续被发现概率，不是消除证据。

8. **回绑 objective 并交接**
   - 做什么：若拿到会话，交给 `credential-extraction`（取材）或 `endpoint-persistence`（要长期据点）；若只是取到一条输出，判断是否已足够推进。
   - 完成标准：下一跳明确。
   - 判停：若这条通道只能取一条输出且 objective 未达成，评估是否值得再开一条通道——每多一条通道就多一组痕迹。

## B — 边界 (Boundary) ★

### 不要用的情况
- 目标强制 SMB 签名且禁用 NTLM：psexec/smbexec 系列大面积失效，且 WinRM 若强制 Kerberos 也需要有效票据而非 hash。
- 有成熟 EDR 的环境里用 psexec 派生会话：服务创建 + 二进制落地是最经典的检测组合，几乎必被抓。
- 只需要读一个文件：开 RDP、建共享、传工具都是过度动作。
- 目标为生产核心业务机且不允许服务重启/中断：服务类通道（含 `sc config`）不可用。

### 已知失败模式
- **2012 上用 `at`**：直接失败，`at` 在新版系统中已弃用。
- **把 `wmic` 无回显当执行失败**：实际已执行，需要带回显的实现来确认。
- **`schtasks` 任务不执行**：建的任务若指定用户未登录，可能不运行。
- **psexec 传参加引号**：报「系统找不到指定的文件」。
- **认证通过但写 ADMIN$ 被拒就当权限不足**：这是 UAC remote restrictions 的令牌过滤，不是共享权限（108 已排除策略问题）。
- **smbexec 直接用 C++ 版**：主流杀软已查杀。
- **DCOM 假设任意机器可用**：依赖目标存在对应 COM 服务器进程与足够权限，借 explorer.exe 才「进程列表无新面孔」。
- **开 3389 / 关防火墙传文件**：09 与 033 两次自评都是弯路；服务器突然开 3389、防火墙被关的告警优先级极高。
- **连不上就反复重试**：09 中改注册表仍连不上，判断是防火墙/白名单后直接放弃才是对的。
- **不清理 PSEXESVC**：异常退出不会自删，服务与文件成为直接溯源线索。

### 作者与时代的局限
- 案例基于 2019–2021 年的 Windows 7/Server 2008R2/2012R2 环境与 CS 4.0。当前主流环境里：SMB signing 默认强制（Win10 24H2 起 SMB 客户端签名默认开启）、NTLM 审计/禁用普及、WinRM 与 WMI 被 EDR 重点监控，本卡「哪些通道能通」的默认值需要按现网重测。
- DCOM 横向在近期 Windows 版本上受「DCOM 加固」（KB5004442 起的 hardening）影响，部分原语需要显式配置才能用。
- 未覆盖 Linux 侧横向（SSH 密钥复用、Ansible/Salt 批量执行面），而 146 的案例表明 Linux 主机往往是凭据链的关键一跳。
- 未讨论「横向被 UEBA 识别」：单次 psexec 是事件，十分钟内对 20 台主机做同样动作是模式，书中只讨论单次痕迹。

### 容易混淆的方法
- **只执行 vs 派生会话**：前者不落文件、不建服务；后者需要落地物或新进程。CS 手册的 `jump` 与 `remote-exec` 分离正是这个区分。
- **remote UAC vs 共享权限**：前者是令牌完整性，表现为「认证过、写不进」；后者是 NTFS/共享 ACL，表现为「连不上或列不出」。
- **横向 vs 中继**：本卡需要已知凭据；中继利用别人的在线认证过程。
- **横向 vs 持久化**：横向是「这一次进去」，持久化是「下次还能进去」；用横向手段顺手做的服务/任务往往成为事实上的持久化，需要显式决定是否保留。

### 授权与合规边界
> 待补充（用户自行填写）
