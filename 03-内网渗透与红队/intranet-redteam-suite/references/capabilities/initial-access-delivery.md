## I — 方法论骨架 (Interpretation)

这个能力解决的是「外部第一个口子从哪来」，以及更关键的：**当最直接的那条投递路径被静默拦掉时，怎么判断被拦、往哪降级**。

外部打点有四类可用的门，每一类的失败方式不同，判断依据也不同：

1. **邮件投递**。链路上有两道独立关卡：网关（看附件类型、看链接信誉、看发件域）和收件人（看内容是否可信）。附件的可执行性最强但最容易被网关整类拦截，而且失败是**静默的**——发送端显示成功，实际没进收件箱。所以判断依据必须是回执指标（Email Opened / Clicked Link / Submitted），不能是「发送成功」。一旦附件被拦，把「可执行体」从邮件里移出去：附件 → 正文下载链接 → 二维码承载链接 → 伪造内部系统登录页直接钓账号。
2. **名单分层**。钓鱼产出 = 点开率 × 单次点开的收益。运维/安全人员点开率低，且一旦收到可疑邮件会去查发件域、上报、封禁，把一次未成功的投递变成一次暴露；普通员工点开率高，账号往往也能进 OA/邮箱/内部系统。所以名单不是越大越好，要先按部门/职位分层，把高警觉人群剔出或延后。
3. **接口面**。前后端分离的站点，页面本身做足了鉴权（session、验证码、登录锁定），但登录页调用的后端 API 是**另一套鉴权模型**，且为了渲染下拉框/自动补全，会返回超出必要范围的字段。抓登录请求就能看到它调了哪个子域与端口；把该接口当独立目标 FUZZ 参数，常能绕过页面层所有防护。判断信号是：登录请求打向与主站不同的域名/端口，且 JS 里引用了该域名。
4. **多因素绕过（设计缺陷型）**。双因素的关键假设是「第二因素在用户手里」。若注册/找回流程允许「账号密码正确就能绑定一台新设备」，攻击者拿到口令后可以自己生成第二因素：绑定 → 用自己的 Authenticator 扫码 → 得到该用户的通行码 → 完成登录。入口不是漏洞，是产品把「身份证明」和「设备注册」合并成同一步。
5. **跨环境重放**。测试系统与生产系统常共用代码甚至共用后端。当某管理接口只按 Host/域名路由、却不校验调用者身份时，在测试环境抓到的请求包把 Host 换成生产域名重放，就会在生产执行同样的写操作。关键判断是「同一功能在两套环境都存在」——此时不该在新环境重新找漏洞，而应先把已有请求跨环境重放。

五条路的共同纪律：**先判断「这条路是否到达」，再判断「到达后是否有用」**。把「发送成功」当「投递成功」、把「页面打不动」当「整站打不动」，是外部打点最常见的两次误判。

## A1 — 应用示例 (Application Example)

### 示例 1: 附件被网关全拦后降级到正文链接与二维码
- **类型与来源**: 【亲历】163 酒仙桥六号部队《邮件钓鱼平台搭建以及基础使用场景》
- **问题/输入**: 已搭好 Gophish 与发信服务器，目标是拿到至少一台终端上线。
- **方法论的使用**: 首轮做「模仿领导」邮件，近 1 小时无人上钩（受众选错）；次轮改投 exe 附件，Gophish 的 Opened 数全为 0 而发送无报错 → 判定被反垃圾网关整类拦截（不是特征码问题，是文件类型问题）；于是把载荷挪到正文内嵌下载链接，落地页提供 exe/文档 → 出现 Opened/Clicked 递进，2 台主机上线；再用二维码承载链接绕过链接检测，钓到 OA 账号并登录后台拿 shell。
- **结论**: 网关拦的是「载体类型」而非「样本特征」，所以降级方向是换载体而不是改免杀；判断依据必须是回执指标。
- **结果**: 原书交代最终拿到 2 台主机与一个 OA 后台 shell。

### 示例 2: 登录口抓包反查后端 API，FUZZ 出全量员工信息
- **类型与来源**: 【亲历】163 酒仙桥六号部队《记一次因 API 接口问题导致目标内网沦陷》
- **问题/输入**: 目标管理系统登录口有验证码与锁定，页面层爆破不动。
- **方法论的使用**: 在登录口抓包，发现请求实际打向 `api.target.com:8090`（与主站不同域不同端口）；翻 JS 找被引用的接口路径与参数名；对该 API 用参数字典 FUZZ（分页、部门、关键字、id 类参数）；接口返回了全部员工的账号/邮箱/手机号/部门/单位区域。
- **结论**: 页面层与接口层是两套鉴权边界，页面有验证码不代表接口有；「另一个域名/端口」是发现它的信号。
- **结果**: 原书交代用这批信息做口令碰撞进入后台，再在订单查询处发现 MSSQL 注入拿到 DBA。作者也说明单纯硬猜弱口令效率低，最终靠历史泄露库的邮箱/手机号导出账号密码才进后台。

### 示例 3: VPN 改版留下的自助绑定入口
- **类型与来源**: 【亲历】163 酒仙桥六号部队《一份通告引发的内网突破》
- **问题/输入**: 目标 VPN 启用了「设备绑定 + 动态口令」，手上有一批账号密码但没有第二因素。
- **方法论的使用**: 从内部通告/APP 公告里拿到 VPN 新登录地址与注册地址（旧地址常仍有人未迁移）；在注册地址用已知账号密码尝试绑定设备——密码错误提示「请重试或联系技术人员」，密码正确则直接进入绑定流程（这一步同时成了账号有效性 oracle）；添加设备、用手机 Authenticator 扫页面二维码完成绑定；用该通行码 + 账号密码登录 VPN。
- **结论**: 当「身份证明」与「设备注册」被合并成一步时，口令本身就足以生成第二因素。
- **结果**: 原书交代进入移动办公平台后经 Citrix 与浏览器插件进内网业务系统；也记录了失败面——「最开始尝试已搜集到的账号密码均不能成功登录，差一点放弃」，多数账号没有 VPN 权限。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要它
1. 钓鱼邮件发了但没人点，怀疑被网关拦，需要判断是「没到」还是「到了没人信」。
2. 需要在有限名单里决定先打谁，避免一次投递就惊动防守方。
3. 登录口有验证码/锁定打不动，需要找页面层之外的鉴权边界。
4. 目标上了 MFA，需要判断是「无解」还是「注册流程有缺陷」。
5. 已进入测试/预发系统，需要判断能否把请求跨环境重放到生产。

### 语言信号（出现这些就该激活）
- 中文：「钓鱼邮件没人点」「附件被邮件网关拦了」「邮件发了但没到收件箱」「钓鱼发给谁」「登录口爆破不出来」「api 接口信息泄露」「vpn 要动态口令」「怎么绕过 MFA」「测试环境能进生产进不去」
- English: "phishing attachment blocked", "emails not landing in inbox", "who to phish first", "front-end api enumeration", "user enumeration via api", "bypass MFA via device enrollment", "replay request to production"

### 与相邻能力的区分
- 与 `external-recon-pretext` 的区别：那张卡决定「以谁的身份出现、说什么」，本卡决定「投递物怎么穿过网关、发给谁、以及非邮件渠道怎么打」。
- 与 `evasion-and-opsec` 的区别：那张卡处理「文件/请求像不像恶意」（免杀与编码），本卡处理「文件类型整类被拒」「名单选错」这类投递层与受众层问题——改免杀救不了被类型拦截的附件。
- 与 `credential-extraction` 的区别：本卡产出「可用账号/会话」，那张卡产出「已控主机上的凭据」。

## E — 可执行步骤 (Execution)

**必需输入**: ①目标域名与邮箱命名规则（或可访问的登录口/注册口）；②一个可控的投递基础设施（发信服务器 + 落地页域名，或可用的接口测试环境）；③本次 objective（拿账号 / 拿终端 / 拿后台权限）。缺 ③ 必须先问，因为三类 objective 对应完全不同的降级路线。
**交付物与完成标准**: 一份「投递记录 + 分层名单 + 可用凭据/会话」：投递记录按轮次写清载体、目标人群、Opened/Clicked/Submitted 三级指标；分层名单标明被剔除的高警觉人群及理由；凭据/会话标注来源与可访问面。完成标准是三级指标出现递进，或明确写下「本轮被 X 层拦截」。

1. **验名单有效性，再做分层**
   - 做什么：用 mailtester / verifyemail / 姓名规则组合验证邮箱，剔除离职与无效地址；按部门/职位打标，把网络管理员、运维、安全部门单独拎出。
   - 完成标准：名单里有「部门/职位」字段；高警觉人群已单列。
   - 判停：若拿不到组织结构信息，先回 `external-recon-pretext` 补组织情报，不要盲目全量群发。

2. **第一轮只投非技术岗，用回执指标判定**
   - 做什么：投递附件型或链接型模板，只看 Gophish 的 Opened / Clicked / Submitted，不看「发送成功」。
   - 完成标准：得到每轮的三级指标数值。
   - 判停：若 Opened 全为 0 且发送无报错 → 判定被网关整类拦截，进第 3 步；若 Opened 有但 Clicked 为 0 → 是内容可信度问题，回 `external-recon-pretext` 重做 pretext，不要改载体。

3. **按「附件 → 链接 → 二维码 → 伪造页」降级**
   - 做什么：附件被拦就改成正文内嵌下载链接（落地页提供 exe/文档/宏文档/CHM/LNK/HTA）；链接被拦就改二维码承载；都不行就伪造目标内部系统（OA/VPN/邮箱）登录页直接钓账号。
   - 完成标准：每一轮只改一个变量（载体），并记录该轮的指标变化。
   - 判停：若连续两轮指标无变化，停止投递——继续投只会累积暴露，转第 4 步的技术侧路径。

4. **在登录口找「另一个鉴权边界」**
   - 做什么：抓登录请求，看实际打向哪个域名/端口；翻 JS 找被引用的接口路径与参数名；对该 API 用参数字典 FUZZ（分页、部门、关键字、id 类参数）。
   - 完成标准：拿到接口返回的字段清单；若含账号/邮箱/手机/部门，即为可用名单源。
   - 判停：若接口有来源限制或鉴权，回到页面层找其它功能点；不要把「接口打不动」当成「站点安全」。

5. **评估 MFA 的注册/找回流程**
   - 做什么：在注册/找回/绑定设备入口，用已知账号密码试探流程分支——密码错误与密码正确的提示是否不同；密码正确时是否直接进入「绑定新设备」。
   - 完成标准：确定「口令是否足以生成第二因素」，以及绑定动作会在管理员侧留下什么记录。
   - 判停：若绑定需要旧设备确认或人工审核，此路不通，转第 3 步的凭据钓鱼（伪造登录页直接收 OTP）。

6. **判断测试/预发与生产是否同源**
   - 做什么：比对目录结构、接口路径、参数名；在测试环境抓一个高价值写操作（如添加管理员）的完整请求包。
   - 完成标准：确认「同一功能在两套环境都存在」。
   - 判停：若功能不一致（例如主站后台没有上传点），换功能点而不是放弃；跨环境重放属写操作，可能污染生产数据，执行前必须确认影响面。

7. **收口与交接**
   - 做什么：把拿到的账号/会话按「能访问什么」标注，交给 `domain-recon-path`（若已进内网）或 `password-attack-reuse`（若只有账号）。
   - 完成标准：每个凭据都写了「验证过能登录什么」，未验证的单独标注。
   - 判停：若所有凭据都无法访问任何系统，回到第 4 步扩大接口面，而不是继续猜口令。

## B — 边界 (Boundary) ★

### 不要用的情况
- 目标有成熟的安全意识培训与内部举报机制：此时「名单分层」的收益被上报速度抵消，一次误投会换来全域黑名单，投递路线整体失效。
- 邮件是唯一投递面且网关做全类型沙箱 detonation：附件与链接都会被动态分析，降级到二维码只能提高「到达率」，不能提高「执行率」。
- 目标是纯内网办公（无外网邮件、无 VPN、无对外业务系统）：外部打点无入口，应转物理/供应链面。
- 需要「可复现的技术结论」时：钓鱼成功率与个人判断强相关，重复投递同一人群的成功率会快速衰减，不能作为稳定测量。

### 已知失败模式
- **把「发送成功」当「投递成功」**：111 中第一批 exe 附件全部被网关拦截，发送端无报错，等于白做。
- **只看打开率**：AddTrackingImage 的打开统计不准（部分客户端不加载隐藏图），只能作参考，必须结合 Clicked/Submitted。
- **受众选错**：111 首轮「模仿领导」邮件近 1 小时零响应；05 明确「运维/安全人员单独写邮箱或者不发」。
- **全量群发惊动防守方**：一次失败后整个域被加进黑名单，后续所有投递失效。
- **用需要备案的国内域名/云主机做落地页**：会被直接拦截，111 中作者被迫改用 IP 访问。
- **只盯页面爆破忽略接口层**：页面可能有验证码而接口没有；119 的突破口正是「另一个域名 + 端口」。
- **拿到账号就硬猜弱口令**：119 作者最终靠历史泄露库导出账号密码才进后台，硬猜效率极低且会触发锁定。
- **把绑定设备当成隐蔽动作**：131 明确绑定会在管理员侧留下设备记录，属可见操作。
- **跨环境重放污染生产**：060 的写操作直接在生产创建了对象，若目标是删除类接口，后果不可逆。

### 作者与时代的局限
- 邮件网关的对抗已进入「全类型沙箱 + 链接实时爬取 + DMARC 强制」阶段，111 中「正文链接绕过」的做法在启用 URL 重写的网关（如 Microsoft Defender for Office 365 的安全链接）下基本失效。
- 3-22 的 VPN 自助绑定是**单例**，依赖特定厂商产品的注册流程实现；同类产品多数已要求旧设备确认或管理员审批，不能当作通用手法。
- 3-25 的接口 FUZZ 依赖「接口未做来源限制」，这在近年 CORS/网关统一鉴权普及后成功率下降；但「前后端两套鉴权模型」这个结构性判断仍然成立。
- 书中案例多为 2019–2021 年的国内中小型目标，缺乏对大规模 Zero Trust 架构（每次请求都校验设备与身份）的讨论——在 Zero Trust 下，即使拿到口令与设备绑定，横向仍会被逐次校验拦住。

### 容易混淆的方法
- **与免杀**：网关拦的是文件**类型**与链接**信誉**，不是特征码；改免杀对「exe 附件整类被拒」无效。
- **与钓鱼话术**：话术解决「点了之后信不信」，本卡解决「能不能到、点了之后能不能执行」。
- **与越权**：普通越权在同一系统内做水平/垂直越权，本卡的跨环境重放是「把请求换目标重放」，判断依据是「两套环境同源」。
- **与目录扫描**：目录扫描在同一个鉴权边界内找路径；本卡的接口面发现是从前端流量里找「另一个鉴权边界」。

### 授权与合规边界
> 待补充（用户自行填写）
