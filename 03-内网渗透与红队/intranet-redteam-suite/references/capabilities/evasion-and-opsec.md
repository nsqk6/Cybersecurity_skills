# 载荷免杀与行动 OPSEC

## R — 原文 (Reading)

> Command and Control data exiting the network must be encrypted. ／ Bottom line up front: Log, log, and log some more!

> — 《Red Team Development and Operations》· Engagement Execution: Tradecraft

> 最后，如果我们将版本 3 编译为 64 位的 payload，我们得到 1/69（仅仅一家检测出）！

> — 《渗透测试实战（第三版·红队版）》· 第 7 章 混淆

> To protect our C2 from being burned, we need to add a redirector in front of our C2.

> — 《Hands-On Red Team Tactics》· 第 11 章 Obfuscating C2s – Introducing Redirectors

## I — 方法论骨架 (Interpretation)

这个能力解决的是「怎么让对手看不见我」，但它不是一种技术，而是**三层互不替代的隐蔽**。把三层混在一起谈，就会出现「改了免杀还是被抓」或「免杀了但基础设施被溯源」这类徒劳。

**第一层：文件/载荷层（像不像恶意）。** 检测面分四层，每层只对特定检测有效，跨层才显著降检出：

| 层 | 手段 | 骗过什么 | 作者实测 |
|---|---|---|---|
| 一：文件外观 | 改扩展名、加版本信息 | 人工判断与粗规则 | 起点 21/66 |
| 二：静态字符串 | 字符串加密（如 ROT6 解密函数）、发布版去掉调试输出 | 特征码 | 14/69 |
| 三：调用形态 | `GetProcAddress` 函数指针，导入表里不再出现 `User32.dll` | 基于导入表的启发式 | — |
| 四：位数与加载方式 | 64 位编译、DLL 反射注入、自定义 stage0 不落盘 | 针对 32 位常见模板的签名 | **1/69** |

关键纪律：**只做单层容易被启发式拦**（书中指出「哪怕修改 shellcode 并添加花指令也仍然会因启发式分析而被标记为恶意」）；**验收必须用与目标同款的本地实时 AV**，不能用在线多引擎——「在真实世界的入侵活动中，我不建议使用 VirusTotal 网站，因为你的病毒样本可能会发送给不同的杀毒软件厂商」。这条反例的适用面比免杀更宽：任何「为了验证效果而把载荷外传」的动作，都要先问「这个平台会不会把它变成对手的情报」。

**第二层：行为/日志层（动作看起来像不像正常运维）。** 主机侧检测最常看两处——命令行与父子进程关系。`argue` 的做法是「以挂起状态用伪参数启动 → 在内存里改成真实参数 → 恢复执行」，于是记录进程启动的检测程序留下的是伪参数；`ppid` 把新进程挂到合法父进程下，破坏「高权限程序生出可疑子进程」这类规则。两者都不改变行为本身，只改变「被记录下来的样子」。

同时要控的是**动作本身的体量与位置**：C2 出网必须加密；执行位置只在 Windows 常规可执行目录（`c:\programdata`、`c:\program files`、`c:\windows\`），不从 `c:\windows\temp` 执行；尽量不落二进制，先用系统自带命令达成；出网源收敛到最少（至少留两条：一条交互、一条休眠备用）；绝不把受限数据（PII/HIPAA/PCI）拉出目标网络，只截图文件名与位置。

**第三层：请求/脚本层（Web 侧字符串）。** 检测系统靠「字面量 + 正则」识别恶意请求（`eval`、`document.cookie`、`system`），所以规避的本质是**让危险字符串在请求里不以连续可读形式出现**，在服务端/浏览器里再拼回来。三种拼法：编码（Base64 + 非 eval 执行原语）、语言自身的类型转换（JS 用 `[]+{}` 拼字符，PHP 用 `$x[0x02]` 取字符）、把 payload 与密钥拆到两个信道（body 放密文，自定义头放 key）——最后一种最强，因为日志通常只记 GET/POST 内容。

**第四层（基础设施层）：反溯源。** 有两条独立的链要切断：

- **样本链**：开启 staging 时，任何人只要知道你的地址就能向你要一份 stage，从中逆出配置（回连地址、profile）。`host_stage=false` 直接关掉这个入口。
- **基础设施链**：中间放重定向器，外界只能看到跳板，重定向器暴露即可抛弃。但这只解决「目标侧可见」，没解决「任何人扫到 C2 就能确认 listener 存在」，所以还要用防火墙把 C2 收口成「仅重定向器可达」——验收判据是从外部扫描 C2 端口应显示 `filtered`。

最后是贯穿全层的元规则：**任何偏离 SOP 的动作都要找资深操作员会商并记录原因**；「Log, log, and log some more」不是文档要求，而是「没记录 = 没发生，没报告 = 没演练」。

## A1 — 应用示例 (Application Example)

### 示例 1: 四层阶梯把 21/66 打到 1/69
- **类型与来源**: 【亲历】《渗透测试实战（第三版·红队版）》第 7 章（ceylogger v1 → v3）
- **问题/输入**: 自写键盘记录器，在 66/69 家引擎上被检出。
- **方法论的使用**: 先测基线（在自有实时 AV 环境，不上传多引擎）；施加第一层（改扩展名/加版本信息）→ 复测 21/66；第二层（字符串加密、发布版去调试宏）→ 14/69；第三层（改函数指针调用，确认导入表不再出现 `User32.dll`）；第四层（改 64 位编译、改反射注入）→ **1/69**；最后在目标同版本 AV 上做终验。
- **结论**: 收益不是线性的，最大一跳来自「位数与加载方式」；但前几层不能跳，否则第三、四层的效果会被前两层的残留特征吃掉。
- **结果**: 原书给出三组检出数（21/66、14/69、1/69）作为各层收益的量级证据。

### 示例 2: argue/ppid 让命令行与进程树「看起来正常」
- **类型与来源**: 【配置说明】《Cobalt Strike 4.0 用户手册（中文翻译）》7.6 备用父进程、7.7 伪造进程参数
- **问题/输入**: 某条命令（如 `net group "domain admins" /domain`）的命令行会被主机检测记录，需要让它看起来无害。
- **方法论的使用**: `argue <命令> <假参数>` 把命令加入伪造列表（匹配是**精确**的：`net.exe` 不会匹配 `NET.EXE` 或带全路径的写法）；通过该 Beacon 执行该命令，确认进程正常起来；`ppid <pid>` 指定备用父进程（当前会话须有调用权限，且最好与目标同桌面会话）；查目标机的主机检测记录验证。
- **结论**: 这条手段不改变行为，只改变「被记录的样子」，因此对「基于行为语义的检测」无效，对「基于命令行字面量与进程树的检测」有效。
- **结果**: 手册未给实战结果；同时列出三条硬约束——伪参数必须留够长度（实际参数比伪参数长则启动失败）、x86 Beacon 只能伪造 x86 子进程参数、ppid 跨会话会露馅。

### 示例 3: 重定向器 + C2 收口，验收看 `filtered`
- **类型与来源**: 【例题】《Hands-On Red Team Tactics》第 11 章
- **问题/输入**: 受害主机的连接表里若出现 C2 真实 IP，蓝队可直接拉黑，行动即断。
- **方法论的使用**: 部署重定向器，用 socat 或 iptables 把入向端口转发到 C2（`iptables -t nat -A PREROUTING -p tcp --dport 8080 -j DNAT --to-destination <C2_IP>:8080` + `MASQUERADE` + `net.ipv4.ip_forward=1`）；在 C2 上加 UFW 只允许重定向器访问监听端口（`ufw allow from <Redirector_IP> to any port 8080 proto tcp`、`ufw deny out to any`）；重定向器上只放行 22 与业务端口；生成 payload 时把 lhost 设为重定向器地址。
- **结论**: 加转发只解决「目标侧可见」，不收口等于「任何人扫到 C2 就能确认 listener 存在」（书中原话）；两个动作必须成对做。验收判据是可观测的：目标连接表只剩重定向器 IP，外部扫描 C2 端口显示 `filtered`。
- **结果**: 书中用重定向器 `35.153.183.204` 与 C2 `54.166.109.171` 演示，两步结果均如预期。

### 示例 4: 反例——用 VirusTotal 验样本
- **类型与来源**: 【亲历】《渗透测试实战（第三版·红队版）》第 7 章
- **问题/输入**: 想知道样本会不会被杀。
- **方法论的使用**: 错误做法是上传多引擎在线扫描；正确做法是建一台与目标同版本杀软/EDR 的隔离测试机，跑实时防护 + 行为监控，记录拦截点，回到对应的层修改，全程不外传样本。
- **结论**: 多引擎会把样本分发给厂商，等于在行动前把自己的武器登记了一遍；隐性代价还包括暴露「有人在造这个样本」的时间点。
- **结果**: 作者明确「然而，它非常适合测试或者学习」，即仅在非实战场景可用。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要它
1. 载荷被杀，需要判断是特征码、导入表还是位数问题。
2. 载荷免杀了但一执行就被行为检测抓，需要看命令行与进程树。
3. Web 侧 payload 被 WAF 拦，需要让危险字符串不以字面量出现。
4. C2 被拉黑或被溯源，需要处理重定向器、staging、端口收口。
5. 需要给团队定 OPSEC 铁律（日志、执行位置、C2 体量、数据外带）。

### 语言信号（出现这些就该激活）
- 中文：「免杀怎么做」「怎么过 AV/EDR」「样本能不能传 VT 看看」「命令行被记录怎么办」「WAF 绕过 payload」「php 混淆 webshell」「C2 怎么防溯源」「host_stage 要不要关」「重定向器怎么配」「红队 OPSEC 怎么做」
- English: "bypass antivirus layers", "is it safe to upload sample to VT", "spoof parent process", "obfuscate payload to bypass WAF", "protect my C2", "redirector setup", "C2 traffic hygiene"

### 与相邻能力的区分
- 与 `initial-access-delivery` 的区别：那张卡处理「文件类型整类被拒、名单选错」这类投递层与受众层问题；本卡处理「文件/请求像不像恶意」。改免杀救不了被类型拦截的附件，反之亦然。
- 与 `c2-tunnel-infrastructure` 的区别：那张卡决定「哪条通道能成立」；本卡决定「通道选定后怎么控体量、怎么防止被溯源」。
- 与 `credential-extraction` 的区别：PPL 绕过/SSP 加载绕的是「能不能读到 lsass」，属访问控制；本卡绕的是「文件与行为像不像恶意」，属检测面。
- 与 `engagement-governance` 的区别：那张卡管「测量对象与报告」，本卡管「动作痕迹」。

## E — 可执行步骤 (Execution)

**必需输入**: ①载荷形态（exe/dll/shellcode/脚本/webshell）；②目标环境（OS 版本、位数、杀软/EDR 型号与版本）；③一个与目标同款的隔离测试机；④本次要规避的检测面（静态/行为/网络/请求）。缺 ②③ 时不得进入验证环节，只能做设计。
**交付物与完成标准**: 一份「隐蔽性验收记录」：每个载荷/请求含「施加减的层 → 检出结果 → 拦截点」三列；基础设施含「外部扫描 C2 的结果（应为 filtered）」。完成标准是目标同版本 AV 上通过、且写下了「它仍暴露在哪一类检测下」。

1. **定检测面与基线**
   - 做什么：在隔离测试机上跑基线检出，记录「拦截发生在哪一层」（静态删除 / 执行时拦截 / 行为阻断 / 网络告警）。
   - 完成标准：基线数字与拦截层都记下来。
   - 判停：若无法搭建同版本测试机，停止免杀工作——用在线多引擎替代等于把样本送出去。

2. **第一层：文件外观**
   - 做什么：改扩展名、补版本信息/签名信息（不伪造签名）、改图标与资源。
   - 完成标准：复测，记录检出数变化。
   - 判停：若基线本就不是「人工判断型」检测（例如纯行为检测），跳过本层，直接进第三层。

3. **第二层：静态字符串**
   - 做什么：字符串加密（加解密函数，如 ROT6）；发布版去掉调试输出宏；去除明显工具名/路径字符串。
   - 完成标准：复测，检出数下降。
   - 判停：若复测出现「检出数不降反升」（加了可疑解密逻辑），回退本层换实现。

4. **第三层：调用形态**
   - 做什么：改用 `GetProcAddress` 取函数指针，避免导入表出现敏感 DLL；检查导入表变化（`dumpbin /imports`）。
   - 完成标准：导入表里不再有敏感条目；复测。
   - 判停：若启发式仍拦（行为特征明显），不要继续加花指令——直接进第四层，或回到设计层重做。

5. **第四层：位数与加载方式**
   - 做什么：64 位编译（匹配目标架构）；改反射注入/自定义 stage0（不落盘）。注意 x86/x64 必须与目标进程一致。
   - 完成标准：复测，检出数显著下降（这一层通常是最大一跳）。
   - 判停：若目标只能是 32 位（老旧系统），本层收益受限，接受更高检出并靠行为层补。

6. **行为层：命令行与进程树**
   - 做什么：对会被记录的命令用 `argue` 伪造参数（注意精确匹配、伪参数长度足够）；用 `ppid` 把进程挂到合法父进程（同会话）；只在标准目录执行（`c:\programdata`、`c:\program files`、`c:\windows\`）。
   - 完成标准：主机检测记录里的命令行与父进程符合预期。
   - 判停：若实际参数比伪参数长导致启动失败，加长伪参数；若 ppid 跨会话，换同会话父进程。

7. **请求层：让字符串不以字面量出现**
   - 做什么：先确定被拦的字面量（`eval`、`document.cookie`、`system`）；编码层用 Base64 + 非 eval 原语（`[].constructor.constructor("code")()`、`Function`、`setTimeout`）；语言层用 JS 的 `[]+{}` 拼字符或 PHP 的 `$x[0x02]`/`\x6f` 取字符；最强的是分信道——密文走 body、密钥走自定义头（`$_SERVER['HTTP_MYHEADER']`）。
   - 完成标准：请求里不含被拦字面量，且执行成功。
   - 判停：若换执行原语后新原语本身也在黑名单（如 `atob(` 被拦），换下一个原语而不是继续编码同一段。

8. **基础设施层：断两条链**
   - 做什么：C2 拓展文件设 `host_stage=false`；为每个出口监听器配独立域名/IP 的重定向器（socat/iptables 转发或云 LB）；在 C2 上用防火墙收口只允许重定向器；用「变体」给不同监听器分配不同流量指标。
   - 完成标准：目标连接表只剩重定向器 IP；**从外部扫描 C2 端口显示 filtered**；关闭 staging 后确认投递方式仍可用。
   - 判停：若收口后自身也连不上，检查 UFW 出向规则；若所有监听器共用一个重定向器，等于没做隔离，按监听器拆开。

9. **日志与偏离记录（元规则）**
   - 做什么：终端自动日志、工具日志、自研工具输出日志、操作员日志（记录「为什么这么做」与对结果的解读）、动作前中后截图；新工具入场前回答五问（留什么痕迹、改哪些文件、流量特征、对特定 OS 版本的副作用、是否创建用户/组或回连更新）。
   - 完成标准：每个成功与失败动作都有对应记录；每个新工具都有五问答案。
   - 判停：若某动作没有日志，视为未发生——不要写进报告；若必须偏离 SOP，先找资深操作员会商并记录原因。

## B — 边界 (Boundary) ★

### 不要用的情况
- 目标部署了 EDR 的「行为链」检测（进程血缘 + 内存扫描 + ETW）：文件层的四层阶梯收益大幅下降，靠改文件外观无法绕过对 `CreateRemoteThread`/`NtMapViewOfSection` 的行为监控。
- 有应用白名单：位数与加载方式的自由度被限制，反射注入常被拦。
- 需要长期隐蔽且目标有流量基线：加密 C2 本身在高基线环境里可能是异常（「是否在内部也加密取决于内网是否有传感器、是否有其它加密流量、加密是否反而更显眼」）。
- 需要外带受限数据：任何免杀都不改变「数据出网即违规」这件事，本卡明确不把 PII/PCI/HIPAA 数据拉出目标网络。

### 已知失败模式
- **只做单层**：改 shellcode 加花指令仍会被启发式标记（第 7 章原话）。
- **用 VirusTotal 验样本**：样本进入厂商库，后续行动直接被拦。
- **`argue` 匹配不上**：匹配是精确的，`net.exe` 不匹配 `NET.EXE` 或带全路径的写法。
- **伪参数太短**：实际参数比伪参数长，命令启动直接失败。
- **位数不匹配**：x86 Beacon 只能伪造 x86 子进程参数，x64 同理；跨架构注入失败。
- **`ppid` 跨会话**：父进程在不同会话，进程树一看就不合理。
- **只加转发不收口**：任何人扫到 C2 都能确认 listener 存在。
- **持久化模块指向短跳域名**：短跳（ST）被烧即永久失联，持久化应写长跳（LT）。
- **所有监听器共用一个重定向器**：一个暴露等于全暴露。
- **在 `c:\windows\temp` 执行**：非标准目录直接被标记。
- **CSV/明文 C2**：被 IDS 抓字符串。

### 作者与时代的局限
- 免杀四层阶梯的实测（21/66 → 1/69）基于 2019 年前后的引擎能力与 32→64 位的签名差异。当前引擎普遍具备 ML 静态评分 + 内存扫描 + 云端信誉，「64 位编译」这一跳的收益已大幅衰减，甚至反向（新位数特征被建模）。
- `argue`/`ppid` 依赖 ETW 采集的字段与时序；现代 EDR 会同时采集内核回调与用户态 hook，单靠伪造参数与父进程已不足以隐蔽。
- 重定向器 + UFW 收口这套做法在云环境里通常由安全组/LB 承担，书中 iptables 步骤是等价实现，但云厂商的流量日志会记录转发关系，隐蔽性假设不同。
- 未讨论「供应链/签名滥用」这一现代主流路径（盗用签名、合法安装包侧载），书中仍以自编译载荷为主。
- 未讨论「检测经济学」：把检出从 21 降到 1 的成本可能是数十小时，而同一时间用来改行为路径（不落盘、不建服务）收益更高。这条权衡书中没有量化。

### 容易混淆的方法
- **免杀 vs 行为规避**：前者改「文件像不像恶意」，后者改「动作像不像运维」。杀软过了但 EDR 行为规则抓到，是两件事。
- **免杀 vs 访问控制绕过**：PPL 绕过、SSP 加载解决「能不能读到 lsass」，与文件检测无关。
- **载荷层规避 vs 请求层规避**：前者是二进制，后者是 HTTP 请求/脚本字符串；编码 JS 不会让 exe 免杀。
- **重定向器 vs 域前置**：重定向器解决 IP 层可达性（目标只看得到跳板）；域前置解决域名层可见性（HTTP 可用时的伪装）。两者不互相替代。
- **staging 关闭 vs 重定向器**：前者断「样本链」（别人要不到 stage），后者断「基础设施链」（别人追不到 C2）。两条链都要断才算完整。
