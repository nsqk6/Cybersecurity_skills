# 决策规则速查 — 云原生与容器安全

| 能力 | 一句话规则 |
|---|---|
| 容器隔离边界评估 | 先按内核隔离/daemon 自身/外部加固三层拆开评估，再按互信关系划分宿主信任域；三层任一为空就不能作为生产安全结论 |
| 容器提权面识别与运行时加固 | 按 privileged→能力位→挂载→运行时加固的顺序排查，先整包后逐位、先文件系统通道后身份与入口，输出提权面清单与逐项加固动作 |
| 容器逃逸路径判定与蜜罐误判 | 三证交叉先判环境，再按容器自身漏洞/配置不当/内核漏洞三分类选路；特权容器查 fdisk+CapEff，组件漏洞查版本+socket 双条件，蜜罐怀疑必须实测复核 |
| Docker daemon/API 暴露面收敛 | 把"传输与监听面（socket/TCP/TLS）"与"主体授权（谁能碰 socket）"分两层独立收敛；无认证 TCP 监听清零，docker 组按可信用户标准逐个审查 |
| 容器网络暴露面收敛 | 分宿主↔外界、容器↔容器、容器↔宿主本地三方向盘点；对外显式写绑定 IP、对内默认拒绝+显式白名单、host 网络视为继承宿主全部本地信任 |
| 镜像与 CI/CD 软件供应链安全 | 镜像段三查一做（来源可信/内容干净/构建可审计 + 多阶段构建），CI/CD 段两判（PPE 三型/依赖名混淆与来源），两段都过才算供应链安全 |
| 容器安全基线与漏洞扫描工具链 | 用 Docker Bench 按 CIS 六维查配置偏差、用 clair 对镜像层查已知 CVE，两类检查分做且只负责"发现"，整改分流到各专项能力 |
| 云上攻击面与责任边界判定 | 按"谁承担后果"把攻击面拆成租户线与平台线，按"控制可见性"用 IaaS/PaaS/SaaS 分界层判责任，输出攻击面+责任对照表并路由到专项卡 |
| 云凭证与对象存储攻击面攻防 | 按搜集→判价值（IAM 粒度/永久 vs STS）→选链（云助手命令/SSRF 元数据）→对象存储五类入口+前端直传判据→RAM 最小权限止血走完整链 |
| 容器与云取证、日志可见性盲区 | 事件先定证据层与控制方；容器 commit 固化可写层+另存元数据后离线分析，云上按服务模型判可见性并核日志三信号，虚拟化盲区用 Hypervisor 层监控与冷启动前置检查补偿 |
| 云平台后渗透横向与配置收集 | 先判起点（控制台权限/虚机权限）并验证管理网可达，再按五类暴露面突破，随后系统性翻计划任务/运维脚本/配置文件提取跨网段凭据，量化影响范围 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
