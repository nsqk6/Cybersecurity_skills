# 注入通道选择：先确认「能不能注入」，再决定「从哪条通道把数据取回来」

## R — 原文 (Reading)

> "If an error or other divergent behavior was observed, submit two single quotation marks together. Databases use two single quotation marks as an escape sequence to represent a literal single quote, so the sequence is interpreted as data within the quoted string rather than the closing string terminator."
>
> 译：若观察到报错或其他异常行为，改为提交两个连续单引号。数据库用两个单引号作为转义序列表示字面单引号，因此该序列会被当作字符串内的数据而非结束符。

> — 《The Web Application Hacker's Handbook》Ch9 Attacking Data Stores / Finding SQL Injection Bugs

> "The core idea is to inject a query that induces a database error contingent on some specified condition. When a database error occurs, it is often externally detectable, either through an HTTP 500 response code or through some kind of error message or anomalous behavior"
>
> 译：核心思路是注入一条「依指定条件触发数据库错误」的查询。数据库错误通常可从外部感知——HTTP 500、错误消息或异常行为。

> — 同上 / Using Inference: Inducing Conditional Errors

> "另一个重要的安全原则是数据与代码分离原则。这一原则广泛适用于各种由于'注入'而引发安全问题的场景。"
>
> — 《白帽子讲 Web 安全》1.7.3 数据与代码分离原则

## I — 方法论骨架 (Interpretation)

这个能力回答的是同一个问题的两半：**「这个参数到底能不能注入」** 与 **「确认之后，用什么通道把数据取回来」**。两半必须分开做，否则会出现两类典型错误——把「单引号报错」当成注入（可能只是输入校验在报错），或明明有回显却去做时间盲注（浪费几十倍时间）。

机制上，所有注入共享一个根因：**拼接点两侧的「数据」与「代码」之间没有不可绕过的边界**。判断方法不是记 payload，而是看边界能不能被数据构造出来：引号能否闭合、占位符是否存在、列名位置是否根本不带引号。因此本能力的第一层是「边界判定」。

第二层是**通道选择**，判据是「这个注入点还能观测到什么」，代价从低到高：

| 可观测的东西 | 通道 | 代价 |
|---|---|---|
| 查询结果回显在页面上 | 联合查询（UNION） | 一次请求可带整表 |
| 页面有可被劫持的可见逻辑（登录成功/失败） | 条件响应（布尔） | 1 bit/请求 |
| 只有错误页/500 可感知 | 条件错误（`1/0` 惰性求值） | 1 bit/请求 |
| 连错误都看不见 | 时间延迟 | 1 bit/请求，且易受网络抖动 |
| 结果、错误都取不回，但目标能出网 | 带外（DNS/HTTP/SMB） | 一次请求可带大量数据 |

第三层是**结构位置**：如果参数落在 `ORDER BY`、列名、表名位置，它不在引号内，常规测试串（`'`、`"`、`../`）全部返回同一错误页，fuzzer 与人工都会当「无异常」跳过——这正是它在现代应用里仍存活的原因。这类位置必须用**行为型**判据（传 1/2/3 看排序是否变化），不能等报错。

最后一条纪律：**探到注入后立刻在同类参数上复测**（同名参数在别的功能、以及参数名本身）。一个点能注，往往意味着同一套 DAO 的其他入口也能注。

## A1 — 应用示例 (Application Example)

### 示例 1: 图书搜索的 UNION 三步提取
- **类型与来源**: 【例题】《The Web Application Hacker's Handbook》Ch9 / The UNION Operator
- **问题/输入**: 图书搜索框 `?title=Wiley`，怀疑拼进 `SELECT ... WHERE title LIKE '%...%'`，页面会回显书名与作者。
- **方法论的使用**: ① 提交 `'` → 报错，提交 `''` → 报错消失，判定单引号确实是定界符；② 递增 NULL：`' UNION SELECT NULL--`、`NULL,NULL`、`NULL,NULL,NULL` … → 某一次注入行出现（多一行空单元格），列数确定；③ 把每个 NULL 依次换成 `'a'` → 页面上出现 `a` 的那一列可承载字符串；④ 用该列取版本串与元数据，再取目标表。
- **结论**: 有回显时，UNION 是成本最低的通道；NULL 之所以好用，是因为它对任何类型都可转换，不会触发类型错误。
- **结果**: 原书示例 `Wiley' UNION SELECT username,password,uid FROM users--` 使用户口令出现在 title 列。

### 示例 2: 无任何错误反馈时的通道降级
- **类型与来源**: 【例题】《The Web Application Hacker's Handbook》Ch9 / mdsec.net/addressbook/44
- **问题/输入**: 一个查询参数，提交引号、双引号都没有任何报错，页面结构也不变。
- **方法论的使用**: ① 先测条件响应：`AND 1=1--` 与 `AND 1=2--` 是否导致两种不同结果（记录条数不同、页面长度不同）；② 若无可见逻辑差异，构造 `(select 1 where <condition> or 1/0=0)` → 条件真则报错（500/错误页），假则不报错；③ 若错误也被吞掉，用时间延迟：MySQL `select if(<cond>,sleep(5),'x')`，重复三次并改变延迟数值，确认延迟随输入系统变化；④ 效率优化：从逐字符改为逐比特（`ASCII(...) & POWER(2,0) > 0`）。
- **结论**: 通道不是选「更强的」，而是选「这个点还能观测到什么的」。
- **结果**: 原书以该实验演示条件响应与时间延迟两条通道，未给出完整拖库结果。

### 示例 3: NoSQL 的 `$ne` 与 `$regex` 两段
- **类型与来源**: 【亲历】《163酒仙桥六号部队__065-NoSql数据库之漏洞利用方法总结》
- **问题/输入**: 自建 PHP + MongoDB 的 login.php，参数为 `user=x&pass=y`。
- **方法论的使用**: ① 把参数改成 `username[$ne]=1&password[$ne]=1` → 登录成功，说明后端把方括号解析成数组，`$ne` 被当操作符；② JSON 形态改 `{"username":{"$ne":1}}` 同判；③ 确认后转盲注：先用 `$eq` 枚举存在用户名，再用 `password[$regex]=.{n}` 定长度，最后逐位 `^<前缀><候选字符>` 追加，以页面 yes/no 为判据；④ 字符集排除 `* + . ? | # & $`，避免 payload 自身被 URL 破坏。
- **结论**: NoSQL 注入不靠语句拼接，靠「解释器把键名当操作符」；SQL 的注释、UNION 在这里完全无效。
- **结果**: 作者用脚本跑出账号与密码。

### 示例 4: 邮箱字段里的延时注入
- **类型与来源**: 【亲历】《泰阿漏洞挖掘自动化赏金技巧手册》技巧 75
- **问题/输入**: 一个「格式校验通过才落库」的 email 输入框，普通 payload 被格式校验挡住。
- **方法论的使用**: ① 利用 RFC 允许的引号本地部分，构造 `"a'-IF(LENGTH(database())>9,SLEEP(7),0)or'1'='1"@a.com`；② 观察响应时间得到 7,854ms；③ 把 `>9` 改成 `=10` 得 8,696ms、改成 `=11` 无延迟 → 判定库名长度 10；④ 三次以上复测排除网络抖动。
- **结论**: 「格式校验」保护的是校验器看到的那一层，落库/查库环节看到的仍是整串。
- **结果**: 作者据此判定库名长度，未继续拖库。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要它
1. 某个参数加引号报错，需要确认「是真注入还是校验在报错」。
2. 确认有注入但没有回显、没有报错，需要判断该走布尔、条件错误还是时间延迟。
3. 目标是能出网的高权限数据库账号，盲注太慢，想知道能否改用带外通道。
4. 参数是排序/列名/表名（`sort=`、`order=`），常规测试串全部「无异常」。
5. 后端是 MongoDB/Redis 而非关系库，SQL payload 全部失效。
6. 代码里用了 `addslashes`/`mysql_real_escape_string`，需要判断「是否真的安全」。

### 语言信号（出现这些就该激活）
- 中文：「这个参数能不能注入」「单引号报错」「盲注怎么办」「没有回显」「排序参数能注入吗」「有回显怎么拖库」「用了转义函数还安全吗」「NoSQL 怎么打」
- English: "SQL injection test", "blind SQLi", "time-based blind", "union select columns", "ORDER BY injection", "out-of-band exfiltration", "nosql injection $ne", "is addslashes enough"

### 与相邻能力的区分
- 与 `command-file-injection` 的区别：本卡的「解释器」是数据库（SQL/NoSQL），那张卡是 OS shell 与语言 `eval`/`include`。探测串不能混用——SQL 的 `1/0` 在 shell 里毫无意义。
- 与 `waf-bypass-encoding` 的区别：本卡假设 payload 能到达 sink；如果 payload 在设备层就被拦，先转那张卡，回来再用本卡的通道。
- 与 `source-code-audit` 的区别：本卡是黑盒判据；白盒时「有没有拼接」可以直接看代码，用那张卡的 grep + 数据流回溯更快。

## E — 可执行步骤 (Execution)

**必需输入**: 一个可疑参数（URL/body/cookie/header 均可）；一个可对照的良性值（原始合法输入）；能读原始响应（含状态码、长度、正文、耗时）的代理。缺「良性值」就无法建基线，必须先取。

**交付物与完成情况**: 一份「注入点 → 边界类型 → 可用通道 → 已取到的证据」清单；完成标准是每条结论都有可重复的对照实验（改一个变量、结果稳定复现三次）。

1. **测边界：引号三步**
   - 做什么：提交 `'` 记录是否报错/结果变化；提交 `''` 看报错是否消失；用各库拼接语法构造等价串（Oracle `'||'FOO`、MS-SQL `'+'FOO`、MySQL `' 'FOO`）看行为是否与良性值一致。
   - 完成标准：能用「等价表达式」证明输入进入了 SQL 求值，而不是被当普通文本。
   - 判停：若 `''` 仍报错，说明不是引号问题，转第 2 步查结构位置。

2. **测结构位置（列名/排序）**
   - 做什么：列出所有控制排序/字段/表名的参数；依次传 1、2、3，看结果顺序是否随之改变；超过列数是否报错；传 `1 ASC --` 与 `1 DESC --` 看能否反向。
   - 完成标准：能区分「ORDER BY 注入」与「SELECT 列名位置」两种。
   - 判停：确认是结构位置后，直接跳到第 4 步（UNION 在此不可用，只能走推断）。

3. **数字型与隐式转换**
   - 做什么：用 `1+1` 替换 `2`；需要更硬证据时用 `67-ASCII('A')`（=2）；单引号被过滤时用 `51-ASCII(1)` 利用隐式类型转换。
   - 完成标准：等价表达式返回与良性值相同的结果。
   - 判停：若全部无差异，转 NoSQL 判据（第 8 步）。

4. **选通道：按可观测副作用排序**
   - 做什么：① 有条件响应 → 用布尔（`AND 1=1` / `AND 1=2`）逐位推断；② 只有错误可见 → 用 `(select 1 where <cond> or 1/0=0)`；③ 连错误都不可见 → 时间延迟（MS-SQL `waitfor delay`、MySQL `sleep()`/`benchmark()`、PostgreSQL `PG_SLEEP`、Oracle 用 `UTL_HTTP` 超时）；④ 目标能出网 → 带外（`openrowset`/`UTL_HTTP`/`UTL_INADDR`/`INTO OUTFILE` 到 SMB）。
   - 完成标准：所选通道连续三次给出稳定、可区分的两种状态。
   - 判停：时间延迟单次 5 秒不可信，必须「改变延迟数值 → 延迟量随之变化」才认；否则回到第 4 步换通道。

5. **有回显时优先 UNION**
   - 做什么：NULL 递增定列数 → 逐个换成 `'a'` 找字符串列 → 取版本串验证通道 → 查元数据（`information_schema`/`all_tables`/`sysobjects`）拿表列名。
   - 完成标准：能在响应里稳定读出任意一条自选字符串。
   - 判停：Oracle 每个 SELECT 必须带 `FROM DUAL`；列类型不兼容（ORA-01790）时继续用 NULL 试探，不要猜类型。

6. **带外通道的选择按「库 + 权限 + 出口」**
   - 做什么：判库后选出口——MS-SQL `openrowset`；Oracle `UTL_HTTP`（HTTP）/`UTL_INADDR`（DNS，通常更容易出网）/`UTL_SMTP`/`UTL_TCP`，11g 有 ACL 时改 `SYS.DBMS_LDAP.INIT`；MySQL `INTO OUTFILE` 到攻击机 SMB 共享。端口优先 80/53。
   - 完成标准：攻击端监听或权威 DNS 上看到目标发起的连接。
   - 判停：出网被禁则退回第 4 步；MySQL OUTFILE 收不到文件时先用嗅探确认目标是否真的发起了入站连接（常见是攻击端 SMB 配置问题）。

7. **NoSQL 两段（判定 → 提取）**
   - 做什么：表单场景 `username[$ne]=1`；JSON 场景 `{"$ne":1}`；确认后 `$regex` 逐位：先 `.{n}` 定长，再 `^前缀<候选>` 追加。
   - 完成标准：能从「登录绕过」升级到「实际读出字段值」。
   - 判停：`$ne=1` 与 `$ne=time` 效果不同，写错会得出「无注入」的错误结论；`$where` 注入需主动补 `;return true;` 才能翻转。

8. **同族复测 + 防护复核**
   - 做什么：把确认的注入点复制到「同名参数在其他功能」「参数名本身」「同类 DAO 的其他接口」；若代码里见到 `addslashes`/`real_escape_string`，检查拼接模板有无引号包裹（无引号则数字型注入仍然成立）。
   - 完成标准：每条结论都标注「检测到 / 未检测到 / 待确认」，并写清判据。
   - 判停：发现宽字节/二次解码/模拟预处理（`ATTR_EMULATE_PREPARES`）迹象时，转 `waf-bypass-encoding` 的编码层章节。

## B — 边界 (Boundary) ★

### 不要用的情况
- 参数被强类型化且服务端做了白名单映射（`sort in ('name','date')`）：此时「注入」不成立，别把时间耗在变形上。
- 目标使用全静态查询 + 只读数据库账号 + 无文件/命令权限：即便注入了也取不到有价值数据，应先评估账号权限再决定投入。
- 纯粹为了「证明有注入」而使用时间延迟：若已有布尔差异，时间延迟只是更慢的同义证据。

### 已知失败模式
- **把单引号报错当注入**：原书明确要用双引号与等价表达式二次确认，否则会把输入校验的报错误判为 SQL 错误。
- **忘记 HTTP 编码**：`&`→`%26`、`=`→`%3d`、空格→`%20`/`+`、字面 `+`→`%2b`、`;`→`%3b`；漏编码会让载荷在到达 sink 前就被改写。
- **在结构位置用 UNION**：`ORDER BY` 处不接受 UNION/WHERE/OR/AND，只能改用嵌套子查询做推断；这是「明明注入了却打不动」的最常见原因。
- **单次时间延迟下结论**：5 秒延迟很可能只是网络抖动，必须改变延迟参数复核。
- **只看渲染后的页面**：UNION 注入行可能只有空单元格，HTML 渲染后几乎不可见，必须看原始响应。
- **把转义函数当安全**：`addslashes` 只转义少数几个字符，无引号拼接时数字型注入照旧成立（原书与 PHP 审计指南均给出该反例）。
- **只测单点**：不把多阶段流程走完，会漏掉「收集齐后统一入库」的注入点。

### 作者与时代的局限
- 书中的报错注入、`information_schema` 用法基于 MySQL 5.x 时代；现代应用的错误页普遍被收敛，报错注入面大幅缩小，通道顺序应更早考虑布尔与带外。
- 预编译普及后，「值位置」的注入减少，但列名/排序位置（无法参数化）仍是主战场，这一点书中已指出，至今有效。
- NoSQL 部分来自单篇实战总结，覆盖 MongoDB 为主；其他 NoSQL（Cassandra/CouchDB/Elasticsearch）的注入形态不同，不能直接套用 `$ne`/`$regex`。

### 容易混淆的方法
- **注入 vs 输入校验失败**：两者都表现为「报错」，区别是校验失败的报错来自应用、注入的报错来自数据库；用双引号与等价表达式可分辨。
- **SQL 注入 vs 通配符问题**：`LIKE` 里 `%`/`_` 未转义只是「用户能控制匹配范围」，不是注入；原书明确指出很多人把两者混淆。
- **盲注 vs 带外**：前者依赖同一条连接的可观测差异，后者依赖目标主动外连；速度与可用性的取舍相反。

### 授权与合规边界
> 待补充（用户自行填写）
