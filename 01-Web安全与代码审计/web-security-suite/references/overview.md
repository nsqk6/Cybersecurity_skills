# Web 安全与代码审计 · 域总览

## 这个域在真实工作中解决什么问题

这个域覆盖「拿到一个 Web 系统（或它的源码），判断它能被怎么打穿」的完整工作链：从把目标拆成可测的资产与功能清单，到逐类漏洞的判定与利用通道选择，再到把发现变成可被受理的结论。它的核心不是记 payload，而是**四类判据**——边界（数据能否变成代码）、身份（这个请求是谁发的、能碰谁的数据）、状态（业务进行到哪一步、允不允许重复）、观测（这个点还能看到什么副作用）。所有能力卡都围绕「找到判据 → 做对照实验 → 用业务后果定级」展开。

## 域的共性失败模式

1. **把「现象」当「判据」**：单引号报错=注入、响应相同=越权、没看到 token=CSRF、页面空白=没有漏洞。四类判断都需要二次否证（等价表达式、业务语义、参数存在性、本地复现）。
2. **混淆「可发」与「可读」**：浏览器能发跨域请求但读不到响应（CSRF 面），`script` 能在本地源执行（信息泄露面）；服务器能发请求但看不到内网服务响应（盲 SSRF）。判错方向会让整条链的设计错误。
3. **跳过「前置条件」直接上载荷**：上传目录是否可执行、目标能否出网、数据库账号权限、classpath 有无 gadget、目录是否可写。原书多次记录「方法没错但环境不支持」被误判为「方法失效」。
4. **只测单步/单点**：多阶段流程只重放第一步、只测一个参数、只测主站。越权、逻辑、认证三类的漏洞大多藏在「第二步」和「另一个入口」。
5. **把设备当补偿控制**：有 WAF 就降低测试深度，或把「扫描器没报」当结论。WAF 看不见映射、认证、会话、访问控制、业务逻辑与 DOM 型 XSS。
6. **用错层的绕过手法**：白名单字符集上用编码绕过、语义分析引擎上用注释拆分、应用层过滤上用分块传输。绕过的前提是「知道哪一层在拦」。
7. **静态可疑直接当漏洞**：看到 `eval()` 就报 RCE、看到 `innerHTML` 就报 XSS。缺「输入可控 + 可达 + 无有效过滤」三个条件之一即为误报。
8. **结论快过验证**：环境未更新、目标已打补丁、已被前人报过。正确顺序是「本地同版本复现 → 证明漏洞真实 → 再排查目标为什么不行」。
