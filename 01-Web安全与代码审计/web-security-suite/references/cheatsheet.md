# 决策规则速查 — Web安全与代码审计

| 能力 | 一句话规则 |
|---|---|
| 攻击面测绘：把「一个域名」拆成可测的功能与资产清单 | 先用人的点击喂代理建功能地图，再按资产外→内扩张，最后用「功能×漏洞」映射出排期表。 |
| 注入通道选择：先确认「能不能注入」，再决定「从哪条通道把数据取回来」 | 先用双引号与等价表达式证明边界可闭合，再按「还能观测到什么」选 UNION/布尔/条件错误/时间/带外。 |
| 命令执行与文件落地：从「能跑一条命令」到「文件落在哪、怎么被执行」 | 先判解释器（shell/eval/include/容器），用时间延迟证明执行，再按「路径确定性×内容可控性×执行条件」选落地通道。 |
| 服务端发起的请求与结构化消息注入 | 找「二次使用点」，定语法层（XML/URL/CRLF/参数/模板），用回连或差分证明「我控制了那条消息」。 |
| XSS：按输出语境选向量，按投递方式判危害 | 唯一串定位落点→按上下文的结束边界字符构造→过滤器三分类绕过→按触发器选投递→按受害者模型定级。 |
| CSRF 与点击劫持：判断「这个请求能不能被借身份发出」 | 逐条否证三条件（特权动作/仅 cookie/参数可预测），再看 token 三属性，最后检查能否 iframe。 |
| 认证与会话：找「哪一步的判断可以被单独满足」 | 先建基线探锁定，再按「异常/顺序/一次性凭据/随机性/签名算法」五类依赖逐个让依赖失效。 |
| 访问控制与 IDOR：用「两个身份 × 同一请求」证明越权 | 每角色两号 + 未登录一份，对每个功能的每个入口做水平/垂直/未授权三向重放，只认「A 的请求拿到 B 的数据」。 |
| 业务逻辑缺陷：找出「若 A 则 B」的隐含假设并让它不成立 | 把功能读成一句假设，用删参数/跳步/反向值/并发去违反它，并以业务后果（订单状态、余额）判定。 |
| 反序列化利用：先证明「字节流会被 readObject」，再决定用哪条链 | 判入口→URLDNS 证明可达→按能否出网分叉→选远程加载或本地 gadget→取结果（回显/盲写）。 |
| 拦截层绕过：先定位「在哪一层失效」，再选对应的变形手法 | 先分清 WAF/应用/协议哪一层在拦，再按「规则→协议→解析→绕开设备」顺序用最小成本手法。 |
| 代码审计：从「哪个入口」到「哪一行」，并按可利用性收敛 | 选入口（反向/功能/正向）→ 搜危险汇聚点 → 回溯可控来源 → 查过滤二元组 → 追父类与权限白名单 → 按可利用性排序实测。 |
| 从发现到交付：模糊测试、复现自证与可受理报告 | 批量探测→三判据筛异常→手工定性→两套环境复现→按受害者模型定级→四要素报告。 |
| Web安全与代码审计 · OCR 增补：方法论框架与判据 | 从 26 个扫描件 OCR 单元中按「方法论框架与判据」检索方法与判据。 |
| Web安全与代码审计 · OCR 增补：可执行配方与排障 | 从 13 个扫描件 OCR 单元中按「可执行配方与排障」检索方法与判据。 |
| Web安全与代码审计 · OCR 增补：反例与失效边界 | 从 8 个扫描件 OCR 单元中按「反例与失效边界」检索方法与判据。 |

> 速查只给结论；需要原文依据、案例或反例时读对应能力卡。
