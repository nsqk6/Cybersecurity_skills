## I — 方法论骨架 (Interpretation)

这张卡处理的是「面对一台未知靶机，怎么推进才不浪费时间」的元层能力。它不负责某个具体漏洞的利用（那些由 `web-recon-source-leak`、`file-read-and-include`、`rce-egress-and-shell`、`lab-privesc` 等承担），而是管**阶段边界、阶段内的搜索策略、以及什么时候止损**。八个单元按三类问题组织：阶段顺序与交付物、阶段内的多路并行、止损与迁移判断。

**第一类：五段推进与阶段交付物**。全书 16 节靶机虽然不同，但每节都固定切成「信息收集 → 漏洞挖掘 → 获取 shell → 提升权限 → 思路总结」。这个结构本身就是可迁移的检查点表：**前一段没拿到交付物就不要进下一段**。突破口的表述也总是一条链——先定位入口漏洞，再转成代码执行，再换持久 shell，最后借本地配置缺陷换 root；换靶机只需替换每段的具体技术，推进逻辑不变。失败模式是跳段：没摸清开放服务就猜漏洞，或在拿 shell 前沉迷提权 exp。反复出现的经验是「以 Web 作为初步的渗透入口」，因为 Web 通常是唯一暴露面。

**第二类：阶段内同时铺开多路线**。面对未知入口不押注单一漏洞，而是把「目录暴破 → 自动扫描 → 手工看包 → 读源码 → 试凭据复用」并列成清单逐条跑。几条路线的信息产出不同：暴破给新页面，扫描给已知漏洞，手工看包给逻辑问题，源码给过滤规则，凭据给捷径；并行推进保证任何一条卡住时，下一条已提供别的信息源，不至于整体停摆。但作者明确警告扫描器不是万能——「框架的通用漏洞，通常扫描不到注入」；Acid 节 Nessus 与 exploit-db 都没找到可用漏洞，最后靠手工与源码。所以只跑扫描器会漏。

**第三类：止损判断，分四种信号**。
1. **自己判断卡住**：给当前卡点设尝试上限（换过 payload、换过工具仍无果），把它「挂起」而不是死磕，转去消费已拿到的其他信息（数据库密码、配置文件、另一个页面）。Billu_b0x 放弃 SQL 注入后从 phpmyadmin 配置拿到 root。
2. **出题人明示止损**：靶机说明里的「不要浪费时间」「提示」是最可靠的信号，它同时透露「那个文件是真实线索」和「混淆只是障眼法」。正确做法是不在解密上花时间但保留它作为线索。
3. **控制暴破线程，别打崩靶机**：靶机是资源受限的虚拟机，目录暴破与注入工具同时高并发会耗尽其进程/连接资源，导致服务假死；现象是「凭据正确却登录失败」，极易误判为密码错误而反复换字典。低线程（如 4）是固定纪律。
4. **跳出远程模型（仅本地靶场）**：远程攻击面全排查完仍无进展时，可在 VMware/VirtualBox 中引导进单用户/恢复模式直接读源码，反推 intended path 后回正常模式重放。这是学习活动路径，**仅用于自己的靶机**，不是对真实目标的攻击方法。

**第四类：靶场到实战的迁移判断，两个错位**。
- **可解性/时间预设错位**：CTF/PWN 一定有可利用漏洞、基础好约 1 小时可解；MISC/Crypto「一定是可解的题目」；实战是「未知的漏洞、未知时间」「未知的壳、未知的算法」。把「必有解、时间可控」的惯性带进实战，会在没有漏洞的系统上硬找。
- **手法频率错位**：实战常见手法（crontab 反弹、redis 空口令挖矿、ssh 证书登录）在靶场里可能首次出现；靶场经典漏洞（老版本服务、过时内核）在现实中已很少存在。所以把靶场当手法训练场而非漏洞清单，遇到成熟环境主动切到「配置错误、凭据复用、暴露服务」这类高频路径。

**四类问题的共同纪律**：用「交付物」而非「动作次数」衡量进度；用「换路线」而非「重复同一动作」应对卡住；用「任务性质（题目/实战）」决定是否假设有解。本卡的输出是一份带阶段交付物、卡点记录、止损决策和迁移标注的推进日志。

## A1 — 应用示例 (Application Example)

### 示例 1: The Ether 的五段推进链
- **类型与来源**: 【亲历】《Vulnhub靶场实战指南》第八节 The Ether
- **问题/输入**: 一台 Boot2root 靶机，不知道从哪开始。
- **方法论的使用**: 侦察拿到 IP/端口/服务（只开 http 与 ssh）；漏洞挖掘阶段发现 PHP 本地文件包含；把 LFI 转成代码执行（SSH 日志写入一句话）；用 MSF 生成木马经一句话植入运行获得持久 shell；枚举发现错误配置的 SUID 程序提权到 root；最后写「思路总结」记录五条突破点。
- **结论**: 五段交付物逐段推进，换靶机只需替换每段技术；突破口是一条链而非孤立漏洞。
- **结果**: 原书以「突破点总结」五条记载该链，具体 flag 值未给。

### 示例 2: Billu_b0x 的多路线并行与放弃注入
- **类型与来源**: 【亲历】《Vulnhub靶场实战指南》第二节 Billu_b0x
- **问题/输入**: 未知入口，同时有 Web、SSH、phpmyadmin 等多个面。
- **方法论的使用**: 目录暴破拿新页面 → 送 AWVS/APPScan 扫描与 burp 手工看包 → 下载源码审计找过滤规则 → 试凭据复用；index.php 的 SQL 注入「花费不少时间」后判定卡住，转去消费已得到的 phpmyadmin 配置，从中拿到 root 绕过注入。
- **结论**: 多路线保证不整体停摆；止损是换一条成本更低的路径达成同一中间目标，不是放弃目标。
- **结果**: 原书记载从 phpmyadmin 配置拿到 root，放弃的 SQLi 不再是必需路径。

### 示例 3: 高线程打崩靶机的误判
- **类型与来源**: 【亲历】《Vulnhub靶场实战指南》第二节 Billu_b0x / 第十二节 BSides
- **问题/输入**: phpmyadmin 有正确密码却无法登录，服务似假死。
- **方法论的使用**: 回溯发现两个工具同时目录暴破与 sqlmap 注入、线程过高，导致 mysql 宕机；识别「是我打崩的」后降低线程（BSides 明确「4 线程」），避免两个工具同时对同一服务暴力请求；必要时重启/重装靶机，但先记录已获得的 IP、路径、凭据（重装后 IP 从 .161 变 .162 引入额外排查）。
- **结论**: 「凭据正确却登录失败」时先怀疑服务状态，而非继续换字典。
- **结果**: 原书记载最终重装虚机恢复，耗费较长时间。

### 示例 4: The Ether 的出题人明示止损
- **类型与来源**: 【亲历】《Vulnhub靶场实战指南》第八节 The Ether
- **问题/输入**: 靶机说明称某文件重要但「不要浪费时间试图去解密这个混淆后的文件」。
- **方法论的使用**: 把该提示记为出题人指令；遇到对应文件不再尝试解密，但保留它作为线索；实际推进靠 LFI + ssh 日志，而非解混淆文件。
- **结论**: 不解密不等于忽略——保留线索但不在解密上投入；忽略提示去硬解是典型时间黑洞。
- **结果**: 原书后续确实靠 LFI+ssh 日志推进。

### 示例 5: 实战迁移的两种错位
- **类型与来源**: 【转述】《打造CTF 肾透测试兴奋混合剂v1.0》/《Vulnhub靶场实战指南》第一节 Breach1.0 / 第十三节 Kioptrix1
- **问题/输入**: 靶场技巧到实战好像不好用。
- **方法论的使用**: 识别任务性质——题目场景可假设「必有解、约 1 小时」，实战场景放弃这两个假设；标注手法频率——crontab 反弹、redis 空口令挖矿在实战常见但靶场里首次遇到，老版本服务/过时内核在实战已很少；遇到成熟环境优先验证凭据、配置错误、暴露服务等高频面。
- **结论**: 把靶场当手法训练场而非漏洞清单；「系统没漏洞（硬找）」是把题场惯性带进实战的失败模式。
- **结果**: 原书以对比表与总结形式给出，未给具体实战赛果。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要它
1. 第一次打 Boot2root 靶机，不知道标准推进流程是什么。
2. 侦察完不知道下一步该干什么，或扫完描没发现漏洞。
3. 某个注入/包含点死活打不进去，纠结要不要继续死磕。
4. 密码明明对却登不上，靶机突然没响应。
5. 靶机说明里有「不要浪费时间」之类的提示，不确定是不是陷阱。
6. 远程攻击面全排查完仍无进展，想知道还有没有别的路。
7. 学完靶场技巧准备做真实授权测试，担心知识用不上。

### 语言信号（出现这些就该激活）
- 中文：「这个靶机从哪开始打」「渗透测试标准流程是什么」「boot2root 怎么推进」「不知道从哪里下手找漏洞」「扫完描没发现漏洞怎么办」「卡了一小时没进展」「要不要继续死磕这个点」「密码明明对却登不上」「靶机突然没响应了」「爆破要开多少线程」「靶机实在找不到漏洞」「能不能直接看靶机源码」「靶机说明里说别做什么」「为什么靶场技巧到实战就废了」
- English: "what's the pentest kill chain for a lab", "where to start on this box", "am I stuck on this vuln", "did I crash the box", "lab skills vs real world", "CTF skills don't work in real pentest"

### 与相邻能力的区分
- 与 `lab-privesc` 的区别：本卡管**阶段顺序与止损判断**，那张卡管**拿到 shell 之后的具体提权路线与配置错误利用**。
- 与 `web-recon-source-leak` 的区别：本卡的源码注释/惯例路径线索用于靶场推进决策；那张卡是 Web 题起手的技术动作清单。
- 与 `awd-attack-defense` 的区别：那张卡管竞赛的攻防运营与轮换节奏，本卡管靶场的阶段推进与止损。
- 与 `misc-forensics-and-encoding` 的区别：那张卡分析附件内容，本卡决定「现在该分析哪个附件、要不要换路线」。

## E — 可执行步骤 (Execution)

**必需输入**: 一台 Boot2root 类靶机，攻击机与靶机同网段；侦察工具（nmap 等）、目录爆破工具、扫描器、代理抓包工具；靶机说明/提示（若有）。若任务性质（题目 vs 实战）不明，先确认，因为这决定能否假设「必有解」。
**交付物与完成标准**: 一份「靶场推进日志」：五个阶段各自的交付物、阶段内试过的路线及信息产出、卡点与止损决策、最终 flag 与思路总结。判据是每段交付物齐全，且卡点有明确的「挂起/换路线/明示止损/跳出模型」记录。

1. **侦察：拿到「开了哪些门」**
   - 做什么：探 IP、端口、服务、Web 路径，列出开放服务清单。
   - 完成标准：能画出开放服务列表，供后续「以 Web 为入口」和日志载体选择使用。
   - 判停：没摸清开放服务就去猜漏洞是跳段，回本步补全；若任务为实战，不假设「必有解」。

2. **漏洞挖掘：同时铺开多路线**
   - 做什么：目录暴破拿新页面 → 新页面分别送扫描器与 burp 手工看包 → 下载可见页面源码审计 → 试凭据复用；控制线程（如 4），避免两个工具同时高并发送同一服务。
   - 完成标准：至少一条路线产出可用信息（新页面/漏洞候选/过滤规则/凭据）。
   - 判停：扫描器无结果不代表无漏洞（作者明确「通常扫描不到注入」），继续手工与源码；出现「凭据正确却登录失败」先查服务是否被自己打崩。

3. **获取 shell：按交付物推进**
   - 做什么：选一个能到达代码执行的入口漏洞，把命令执行换成可交互 shell；具体技术转 `file-read-and-include` / `rce-egress-and-shell`。
   - 完成标准：能稳定执行 `id` 等命令。
   - 判停：拿 shell 前不要沉迷提权 exp；日志包含等具体卡点按对应能力卡处置。

4. **提权与 flag：转给提权卡**
   - 做什么：按 `lab-privesc` 的路线排序推进到 root，读 flag。
   - 完成标准：拿到 flag 并验证。
   - 判停：提权卡点同样适用本卡的止损纪律，不无限死磕。

5. **卡住时按四级信号止损**
   - 做什么：(a) 自判卡住 → 挂起当前点，消费已得凭据/配置/路径走更短路径；(b) 出题人明示「不要浪费时间」→ 不在该点投入但保留线索；(c) 靶机响应异常 → 先查是不是自己高线程打崩，降线程/记录状态后恢复；(d) 远程面全排查无果且是本地靶机 → 单用户模式读源码反推 intended path，回正常模式重放。
   - 完成标准：每条止损有明确理由与替代动作；单用户模式仅在本地靶机使用。
   - 判停：(d) 绝不可迁移到真实目标；挂起不等于放弃目标，换路径达成同一中间目标即可。

6. **写思路总结与迁移标注**
   - 做什么：记录突破点链、踩坑、所用手法在实战中的出现频率与前提；判断当前是题目还是实战，标注是否假设了可解性。
   - 完成标准：日志可供下一靶复用；迁移判断明确。
   - 判停：把靶场老漏洞清单当实战武器库、或在没有漏洞的系统上硬找，都是迁移失败模式。

## B — 边界 (Boundary) ★

### 不要用的情况
- 真实授权渗透测试：本卡的「必有解」预设、单用户模式读源码、低线程靶场纪律都需重新评估；转真实渗透的方法论，不使用本卡第 5 步 (d)。
- 解题赛（Jeopardy）单题：没有「阶段推进」的靶机结构，本卡的阶段交付物表不适用。
- AWD 竞赛：由 `awd-attack-defense` 接管，本卡不管轮换与 check。
- 单个漏洞的技术细节：本卡只决定「何时用哪个能力」，具体利用转对应卡。

### 已知失败模式
- 跳段：没摸清开放服务就猜漏洞，或拿 shell 前沉迷提权 exp（Vulnhub 各节）。
- 只跑扫描器：作者警告「框架的通用漏洞，通常扫描不到注入」；Acid 节 Nessus 与 exploit-db 均无结果，靠手工与源码。
- 死磕单点：作者在 index.php 注入上「花费不少时间」才转向 phpmyadmin（Billu_b0x）。
- 高线程打崩靶机：双工具高并发导致 mysql 宕机，表现为「密码正确却登不上」，最终重装且 IP 变化引入额外成本（Billu_b0x / BSides）。
- 忽略出题人明示提示去硬解混淆文件，是典型时间黑洞（The Ether）。
- 只猜路径不暴破，或一上来全字典暴破：前者漏非常规目录，后者浪费时间并有打崩风险（Acid / Billu_b0x）。
- 把「必有解、约 1 小时」的题场惯性带进实战，在没有漏洞的系统上硬找（混合剂 v1.0）。
- 把靶场老漏洞清单当实战武器库，或在真实环境漏掉 crontab/证书登录等高频路径（Breach1.0 / Kioptrix1）。

### 作者与时代的局限
- Vulnhub 靶机是教学环境，出题人故意留低门槛线索；成熟实战环境不会这样设计。
- 两个「迁移」单元来自讲者对比与作者总结，属经验性判断而非可量化规则，需按具体实战环境校准。
- 单用户模式读源码依赖对虚拟机镜像的本地控制权，云靶场/远程靶机不适用。
- 低线程「4 线程」是针对当时资源受限虚拟机的经验值，非通用阈值。
- 两本书都没有给出「阶段卡住多久该止损」的量化标准，本卡只能给出信号类型。

### 容易混淆的方法
- **阶段边界 vs 阶段内策略**：本卡第 1~4 步管阶段边界（交付物），第 2 步的多路线管阶段内搜索。
- **自己判断卡住 vs 出题人明示止损**：前者是自己设尝试上限后换路线，后者是服从外部提示但不忽略线索。
- **挂起/换路线 vs 跳出远程模型**：前者仍在远程模型内换路径，后者（单用户模式）跳出远程模型，仅本地靶场可用。
- **可解性预设错位 vs 手法频率错位**：前者讲「有没有解、要多久」，后者讲「哪些手法在实战常见」。
- **本卡止损 vs `lab-privesc` 的失败排查**：本卡决定「换不换路线」，那张卡处理「已选路线里的具体失败」（如架构位数、无编译器）。
