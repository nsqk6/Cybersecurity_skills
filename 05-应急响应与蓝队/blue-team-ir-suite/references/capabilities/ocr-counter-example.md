## I — 方法论骨架 (Interpretation)

**策略优化反例——缺什么补什么不拆东墙补西墙** — 策略优化有两条红线：①不要拆东墙补西墙——为补一个洞而开新洞（例如为方便监测把隔离策略放开）；②缺什么补什么——按需补齐而不是堆砌。优化要按"安全技术 / 安全管理 / 安全运营"三条线分别审视：技术看缺什么、管理看岗位职责/章程/制度是否清晰合理、运营看流程是否有缺陷。同时要"定期优化"与"验证有效性"，避免策略老化。

**DDoS 防御自动化阈值与脉冲攻击局限** — DDoS 防御的本质局限：①自动化靠阈值触发，做不到秒级响应；②近源清洗触发到响应延时长；③云清洗依赖 DNS 递归生效，TTL 长达 24 小时；④ADS 学习能力有限，大促日正常流量可能触发攻击判定；⑤全局策略对子业务不灵敏，可能子业务 CARD 了全局策略还没触发；⑥变换形式攻击仍需人工识别。攻击者利用这些灰度期发起脉冲攻击（≤5 分钟突刺），等防御启动就跑。

**反例——基础未稳就建 SOC** — 反模式：基础未稳就建 SOC。SOC 是金字塔顶，依赖底层地基（基础数据源、告警误报解决、纵深防御体系）。在底层未稳时建 SOC 只会成摆设——日志多但没人看，800 年不会看的日志堆在 SOC 里。初期应聚焦"有切实需求且有人会去关注"的日志（如非堡垒机发起的 SSH 成功登录），通过 syslogd 集中存储，是否用 ELK/splunk 看具体需求。

**反例——SSH 直连被黑机器查 rootkit** — 应急响应的常见反模式：接到入侵报告后慌乱 SSH 直接连被黑机器查 rootkit。问题：①心理状态差容易出错；②没备份就操作可能"把系统搞震了"；③出意外后自己变罪魁祸首。正确做法是先冷静，按 PDCERF 走 Preparation（用静态编译工具、有快照/回滚能力），不在慌乱状态下直接登录操作。

## E — 执行步骤 (Execution)

### 策略优化反例——缺什么补什么不拆东墙补西墙

1. 按技术/管理/运营三条线分别列出当前缺口 → 完成判据：三线缺口清单
  2. 对每个补齐动作评估是否会拆东墙（影响其他策略） → 完成判据：影响评估记录
  3. 定期复审策略有效性（建议每演练一轮一次） → 完成判据：复审记录

### DDoS 防御自动化阈值与脉冲攻击局限

1. 评估自身检测方式（逐流 netflow 抽样 vs 逐包） → 完成判据：检测精度与响应时长
  2. 对子业务单独配策略，不依赖全局 → 完成判据：子业务级 DDoS 策略
  3. 大促前人工预调 ADS 学习基线 → 完成判据：基线调整记录
  4. 保留专家人工介入通道，应对变种攻击 → 完成判据：专家值守排班

### 反例——基础未稳就建 SOC

1. 评估底层地基：纵深防御是否就绪？告警误报率？关键数据源是否就位？ → 完成判据：地基评估表
  2. 初期只接"切实需求 + 有人关注"的日志（如 /var/log/secure 中非堡垒机登录） → 完成判据：日志白名单
  3. 地基稳后再评估建 SOC → 完成判据：SOC 立项前置条件达成

### 反例——SSH 直连被黑机器查 rootkit

1. 接到报告后先冷静评估事件级别与影响 → 完成判据：事件级别判定
  2. 确保有快照/回滚能力后再操作 → 完成判据：回滚预案就位
  3. 用事前准备好的静态编译工具（ls/ifconfig/ps 等）排查 → 完成判据：使用工具箱而非系统自带可能被替换的命令

## B — 失效与边界 (Boundary)

- **策略优化反例——缺什么补什么不拆东墙补西墙**：为补漏洞放宽访问控制，结果把内网暴露面扩大；只优化技术策略不优化管理章程，导致策略落不到执行层；策略写了不验证，几年后失效无人知晓。
- **DDoS 防御自动化阈值与脉冲攻击局限**：全信厂商"秒级响应"宣传，不做人工预案；或全用全局策略导致子业务被打而全局未触发。
- **反例——基础未稳就建 SOC**：看 PPT 多了听厂商介绍就上 SOC——日志堆成摆设，安全团队没人看；或全量日志接入，硬件与人力成本爆炸。
- **反例——SSH 直连被黑机器查 rootkit**：慌乱直接 SSH + 用系统自带 ps/ls（可能被 rootkit 替换） → 误判；或没备份就操作，把业务搞挂，自己背锅。
