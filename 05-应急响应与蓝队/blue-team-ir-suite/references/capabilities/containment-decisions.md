# 抑制与隔离决策

## R — 原文 (Reading)

> 在不影响主业务运行的情况下，对受害机器：拔网线啊！拔网线啊！拔网线啊！…… 并且，切断网络连接可使挖矿现场尽量保持完整，有助于接下来的溯源工作顺利开展。

> — 《136-手把手教你做挖矿应急响应》· 一、3、临时抑制挖矿

> 不建议关闭受感染的计算机。 某些类型的恶意软件保留在内存中，并且不会在硬盘上创建文件

> — 《inclident-response-guide》· 推荐的 IR 流程和规则 · 隔离受攻击的计算机

> 从攻击者渗透进入内部网络的某一台主机到执行加密行为往往有一段时间，如果在这段时间能够做出响应，完全可以避免勒索事件的发生

> — 《勒索病毒应急与响应手册V1.0》· 第一章

## I — 方法论骨架 (Interpretation)

这个能力解决的问题是：**事件正在发生，必须立刻决定"断什么、不断什么、先救什么"。**

抑制的本质是在三个损失之间取最小值：

- **扩散损失**：横向、加密、外传，随时间线性甚至指数增长；
- **证据损失**：关机、杀进程、重装销毁易失证据，事后无法定损定责；
- **业务损失**：断网、停机、隔离造成的可用性中断。

关键洞察是：**关机是唯一同时增加扩散损失和证据损失的选项**（既没阻断网络——恶意程序可能已在别处——又销毁了内存证据），所以在绝大多数场景下它是错误的第一动作。正确的替代手段是**逻辑/网络层隔离**：改路由、改防火墙 ACL、禁用交换机端口、把主机移入隔离 VLAN。这样恶意程序连不到内网与互联网，但主机继续运行，内存态、连接表、C2 配置、解密密钥全部保留。

因此抑制手段按"可逆性 + 覆盖面"排序，从上往下选：

1. **收紧网络策略**（封单个 C2 IP/域名、封矿池、封横向端口 135/139/445/3389）：最精准，业务影响最小，但只能挡住已知目标。
2. **网络层隔离**（ACL/VLAN/交换机端口）：覆盖面大，保留主机运行，需网络团队协同。
3. **主机侧逻辑隔离**（禁用网卡、拔网线）：一线可独立完成，但**部分恶意样本会监测网络状态，发现断网一段时间即自毁痕迹**，因此不如网络侧隔离。
4. **暂停/冻结虚拟机**：云环境最优，保留内存态；但会中断业务。
5. **关机**：最后手段，仅在"加密正在扩散且无法从网络侧阻断"时使用，且必须记录取舍理由。

再叠加场景分支，因为不同事件的"止血点"不同：

- **勒索**：有两个窗口。加密前（从入口到执行加密器常有数小时到数天的横向时间）响应就是止损，重点是找扩散迹象；加密后唯一能挽回的是备份，顺序是**隔离 → 查备份 → 定家族 → 恢复**，绝不能先研究解密。
- **钓鱼**：目标是"人"不是"服务器"。终端可以直接断网甚至关机（个人机证据价值低），远控类在防火墙双向封 C2。
- **挖矿**：顺序必须是**断矿池 → 拆驻留 → 删文件**。断矿池既切断收益，又让"是否还有残留"变得可观测（断了还连，说明还有备用矿池）。
- **蠕虫式批量感染**：规模超出逐台操作能力时，改用"投喂式"批量清除（劫持恶意域名，让病毒自己下载清除脚本）。
- **多点潜伏**：抑制不等于清理。清掉最显眼的那个据点会让其余据点转入静默，必须先梳理攻击链再动手。

一条容易被忽略的计数：**批量改密时不要改成同一个新口令**。把几十台机器改成同一个密码，等于把定损结果重新合并成一组新的"共性"，下一次横向移动只需要一个口令。

## A1 — 应用示例 (Application Example)

### 示例 1: 勒索事件的两个分支
- **类型与来源**: 【转述】《勒索病毒应急与响应手册V1.0》· 第一章/第二章；《网络安全应急响应技术实战指南》· 4.2.1–4.2.4
- **问题/输入**: 多台服务器出现异常后缀文件与勒索信，部分业务已中断。
- **方法论的使用**: 先判状态——统一异常后缀 + 勒索信 = 已加密。立即隔离：断网/禁用网卡/禁无线 + 关 135/139/445/3389 + 改管理员密码（同网段一并改），因为部分家族 1–2 分钟就能感染一台。然后**不研究解密**，先查核心业务、生产线、备份系统是否受影响；备份安全则损失可控。再定家族（勒索信文本、后缀、联系邮箱）→ 查公开解密工具 → 恢复时优先用异机/异地备份，恢复前确认病毒已清除。
- **结论**: 勒索的分支点不是"怎么杀病毒"，而是"备份是否安全"。
- **结果**: 原书明确把"先研究解密再查备份"列为错过最佳恢复窗口的错误顺序。

### 示例 2: 两条毁证操作
- **类型与来源**: 【转述】《网络安全应急响应技术实战指南》· 4.3 错误处置方法
- **问题/输入**: 财务机被加密，用户想"赶紧拿 U 盘把剩下的文件拷出来"。
- **方法论的使用**: 判断加密进程是否仍在运行——在运行，则任何新接入的介质都会被遍历并加密，损失从一台机器扩大到"所有接过的盘"；同时反复读写会让"读原文件→加密→写回→删除"流程留下的未分配空间残留被新数据覆盖，把"可能恢复"变成"确定不可恢复"。
- **结论**: 需要外部存储时，只能在已隔离且确认无加密进程的主机上操作，或先做只读镜像再离线处理。
- **结果**: 原书把这两类操作单列为"错误操作/错误原理"，并给出加密流程作为解释。

### 示例 3: 几百台机器的批量清除（合成演练）
- **类型与来源**: 【合成演练】按本卡 E 段推演；机制与结果数据出自《076-一次病毒应急的学与思》
- **问题/输入**: 蠕虫式病毒通过计划任务定时拉取 powershell 再下载 exe，杀软只能杀掉释放出来的 exe，powershell 不断重新释放。
- **方法论的使用**: 判定"杀 exe 无用"→ 与网络/机房确认可断外网范围 → 内网 DNS 把恶意域名解析到内网服务器 → 该服务器对**任意路径**都返回"递归删除含 powershell 的计划任务 + 重启 Schedule 服务 + 杀 powershell 进程"的脚本 → 观察 Web 日志确认执行覆盖率。
- **结论**: 连续抑制手段失效时，把攻击者的分发通道变成自己的分发通道，比逐台处置更快。
- **结果**: 原书记录的实测为：17:10 禁外网并劫持域名，17:40 开始返回查杀脚本，22:00 第一波结束、清理 1200 多台，全过程 3 天。此处仅转述该书数据，不作为本卡的普适预期。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要它
1. 事件刚确认，需要决定"先断网还是先取证""要不要关机"。
2. 勒索正在进行，需要判断先隔离、先查备份还是先解密。
3. 一线人员还在路上，需要给现场人员一个"现在就做"的动作。
4. 感染规模大到无法逐台处理，需要批量处置方案。
5. 清理完发现攻击者"死灰复燃"，需要判断抑制与清理的边界。

### 语言信号（出现这些就该激活）
- 中文：「先断网还是先取证」「要不要关机」「拔网线是不是最安全」「中了勒索要不要交钱」「杀了又起来」「几百台中招怎么清」「隔离怎么做」
- English: "containment before forensics", "should I isolate or shut down", "ransomware containment first steps", "mass remediation", "block the C2 or pull the cable"

### 与相邻能力的区分
- 与 `ir-evidence-order` 的区别：那张卡给整条作业链的顺序；本卡只解决"抑制"这一个决策点，并给出各场景的止血分支。两者在"先断网"与"先取证"的表面冲突上互补——断网不毁证据，关机才毁。
- 与 `incident-scoping` 的区别：本卡决定"现在挡住什么"，那张卡决定"还有哪些机器受影响、攻击链怎么走"。
- 与 `persistence-sweep-windows` 的区别：本卡是止血，那张卡是拆驻留；挖矿场景里本卡的"断矿池"必须早于拆驻留。

## E — 可执行步骤 (Execution)

**必需输入**: 受害主机清单与网络位置、攻击者已知的 C2/矿池地址（可空）、业务影响评估（能否断网/能否停机/有哪些依赖）、可用的隔离手段（防火墙/ACL/VLAN/虚拟化平台）、备份系统状态与恢复能力、事件类型初判。

**交付物与完成标准**: 一份《抑制决策记录》，含：选定手段及理由、影响范围（哪些业务/哪些用户）、执行人与时间、回滚方式、观察指标（是否仍有外连/是否仍有新增加密）。完成标准是"扩散停止且证据未被人为销毁"。

1. **判定是否需要立即抑制**
   - 做什么：看三个信号——是否有活跃外连、是否有横向迹象（同网段多台告警）、是否有数据被加密或外传。
   - 完成标准：能回答"再等一小时会多损失什么"。
   - 判停：三个信号都无且事件已结束（如一次性钓鱼投递），跳过强抑制，直接进处置。

2. **选抑制手段（按可逆性排序）**
   - 做什么：优先收紧网络策略（封 C2/矿池/横向端口）；其次网络层隔离（ACL/VLAN）；再次主机侧禁网卡/拔网线；云环境优先暂停/冻结；关机只在"加密正在扩散且网络侧无法阻断"时选。
   - 完成标准：手段与影响面对齐，业务方书面确认。
   - 判停：若只能选关机，先在记录里写明"将丢失内存证据"，并尽量先导内存。

3. **执行隔离并保留运行状态**
   - 做什么：隔离后**不重启、不注销、不关服务**；确认主机仍可被取证工具访问（带外、跳板机、只读通道）。
   - 完成标准：恶意程序无法外连，主机仍在线可采证。
   - 判停：若样本出现自毁迹象（日志突然中断、进程自杀），立即转内存镜像采集，不要继续等待。

4. **分支：勒索**
   - 做什么：先判"未加密/已加密"。未加密：找扩散迹象、封横向端口、改同网段口令（每台不同）。已加密：查备份是否安全（是否在同一 LAN、是否可被生产写入）→ 定家族 → 恢复。
   - 完成标准：备份安全性有明确结论；恢复来源已确认未被加密。
   - 判停：备份也被加密时，转数据恢复路径（只读镜像 + 未分配空间恢复），不要再在生产盘上尝试。

5. **分支：挖矿/蠕虫**
   - 做什么：双向封矿池/C2 → 清计划任务与自启 → 清服务 → 停进程 → 删文件 → 观察。批量场景改用投喂式清除，并在 Web 日志上统计执行覆盖率。
   - 完成标准：无矿池外连、无新增定时任务、CPU 回落并持续一个观察周期。
   - 判停：若封了一个地址仍有外连，说明存在备用地址，按 IOC 全量封禁后再继续。

6. **分支：钓鱼**
   - 做什么：先断传播（终端断网、防火墙双向封 C2）→ 定性方式 → 分"收到的人/点击的人"两份清单 → 隔离受害主机 → 分析被钓原因 → 加固（通报、培训、网关、区域重划）。
   - 完成标准：不再新增受害；两份清单齐全。
   - 判停：若同批收件人中有高权限账号点击，优先处置该账号（改密、撤销会话、查横向）。

7. **分支：多点潜伏**
   - 做什么：**不先删**。先梳理攻击链（入口、落脚点、横移路径、可能的其他据点），再统一清理；清理时用专用跳板、禁止把本地磁盘/剪贴板挂载到受害机（否则等于给攻击者开新入口）。
   - 完成标准：攻击链有完整时间线；清理覆盖全部已知据点。
   - 判停：若清理后仍有告警，回到攻击链梳理，不要重复删同一个点。

8. **观察与解除**
   - 做什么：隔离后持续观察外连、DNS、异常登录、新增文件；解除隔离前确认无复发信号。
   - 完成标准：观察期内无复发，解除动作有记录。
   - 判停：若观察期内出现同类信号，说明根除未完成，转 `persistence-sweep-windows` 或 `incident-scoping`。

## B — 边界 (Boundary) ★

### 不要用的情况
- **纯数据泄露（无活跃外连）**：抑制重点在止损与取证，不在断网；断网可能激怒对手提前公开数据。
- **单机、已离线、无横向迹象**：过度隔离只增加业务成本。
- **业务系统无法停机且网络侧无隔离能力**：此时"抑制"退化为"监测 + 限速 + 精确封禁"，不要承诺"已阻断"。

### 已知失败模式
- **不隔离先分析**：边分析边扩散（勒索场景尤其致命）。
- **禁用网卡代替网络侧隔离**：部分样本监测断网后自毁痕迹。
- **断网后直接重启**：把内存证据一起丢掉。
- **先研究解密再查备份**：错过恢复窗口。
- **在被感染主机上插 U 盘拷文件**：介质被遍历加密。
- **用数据恢复软件在原盘反复扫描**：覆盖未分配空间残留。
- **只清一个据点**：攻击者刻意布置异构多点，其余据点转静默（《蓝队视角下的防御体系突破》· 多点潜伏）。
- **批量改密改成同一个口令**：把定损结果重新合并成新共性。
- **用实时复制当备份**：加密文件被同步到备份端，主备同时失效（《反勒索软件指南》· 七 · 3）。
- **远程处置时把本地磁盘挂载到受害机**：给潜伏者提供新攻击面。

### 作者与时代的局限
- "拔网线"与"不关机"的主张来自不同作者、不同场景（前者针对挖矿、后者针对内存马），原书未统一成决策树；本卡按"是否销毁内存"这一条判据做了合并，属于二次归纳。
- 云环境的"暂停/冻结"在各平台行为不同（是否保留内存、是否计费、是否触发健康检查摘除），原书只有一句提示。
- 未覆盖 OT/工控场景：停机可能造成物理损害，抑制顺序需另立。
- 批量投喂式清除依赖"病毒按域名下载"这一前提，硬编码 IP 的样本不适用，原书未给替代方案。

### 容易混淆的方法
- **"抑制"与"根除"**：抑制是限损（可以牺牲完整性），根除是消除根因（必须找到入口）。
- **"隔离"与"关机"**：前者保留运行态，后者销毁；两者在证据价值上相反。
- **"断网"与"封 IP"**：断网覆盖面大但会触发自毁逻辑，封 IP 精准但只挡已知目标。
- **"备份"与"容灾复制"**：前者要能回到历史时间点且攻击者写不进，后者只保证"有一份最新的"，而最新的可能是加密后的。
