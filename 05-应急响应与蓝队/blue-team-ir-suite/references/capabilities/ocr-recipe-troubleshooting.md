## I — 方法论骨架 (Interpretation)

**Delphi 法四轮建立指标体系** — 四轮 Delphi 法收敛专家意见建立指标体系。第一轮开放式收集；第二轮按反馈分类成四个分指标再问；第三轮剔除与补充；第四轮确认收敛。这种渐进收敛避免单次调查的主观偏差，最终指标体系有专家共识背书。专家选择遵循熟悉原则、知名原则、自愿原则、专业配比原则、年龄层次原则、基本人数原则（10-20 人）。

**跨时间维度漏洞布防——临时规避措施** — 漏洞公布到补丁部署之间存在窗口，期间用"临时规避措施"布防：访问控制缩源、WAF/IPS 加临时规则、临时去权限、必要时直接关服务。这是"治标"但能赢时间。本质是把跨时间维度的防御转成跨空间维度的多点设防，等业务补丁就绪后再撤临时规则。

**WAF 性能优化——算法分层筛选与正则引擎选型** — WAF 性能优化两层：①算法层——流量层层筛选，先用低成本过滤（IP/URL/方法），把流量缩减到最小集再进正则；②引擎层——默认用 RE2（快速高效），但 RE2 对二进制流（如图片中隐含恶意代码）匹配有问题，需要支持规则级引擎切换，遇到二进制场景切到 PCRE。核心思想是"不要让所有流量都进最贵的正则引擎"。

**提权行为检测规则——高权限子进程父进程低权限** — 提权攻击的不可变特征是"exploit 工具自身低权限运行，得到的 shell 高权限"。检测规则抓这个特征：高权限进程（uid=0 / system）的父进程是低权限（uid>0），则告警。规则数据采集需求很少：进程权限、进程 ID、父进程 ID。这种规则不依赖具体 CVE，所有本地提权漏洞利用都符合此模式，避免为每个 CVE 写规则。

**反连木马检测规则——bash STDIN/STDOUT 绑定 socket** — 常见反连木马核心代码模式固定：connect → dup2(sockfd, 1) → dup2(sockfd, 2) → execve("/bin/sh")。检测抓这个不变特征：正常 bash 进程不会有网络连接，若 bash 的 STDIN/STDOUT 绑定了 socket 则判定为木马。规则极简，不依赖木马变种。但对 mod_rootme 这类为复用 Apache 端口做精巧变换的后门不适用，需要根据其"≥2 个 root 权限 httpd 进程 + ≥66 个管道"等异常行为另行建模。

**多系统数据关联检测——NIDS 文件上传 + HIDS CGI 创建** — 单系统检测易被绕过，跨系统关联能抓不变行为。webshell 上传场景：NIDS 检测到非正常业务的文件上传 + 几乎同时 HIDS 检测到 CGI 文件生成 → 判定可疑 webshell。这样不必为每个 Web 漏洞建规则，所有上传类漏洞利用都符合此行为模式。多系统联动的前提是去信息孤岛（CU-2-12 第 11 原则）。

## E — 执行步骤 (Execution)

### Delphi 法四轮建立指标体系

1. 第一轮：开放式调查表收集影响因素 → 完成判据：第一轮回收表
  2. 第二轮：按反馈分四个分指标（物理环境/硬件/软件/管理者）再问 → 完成判据：第二轮回收表
  3. 第三轮：对已有指标做剔除与补充判断 → 完成判据：第三轮回收表
  4. 第四轮：确认收敛得出指标体系 → 完成判据：指标体系文档（含专家签字）

### 跨时间维度漏洞布防——临时规避措施

1. 漏洞情报到达 → 立即评估影响范围与利用场景 → 完成判据：影响资产清单
  2. 在补丁窗口内选择临时规避手段（限 src.ip / WAF 规则 / 去权限 / 关服务） → 完成判据：高危资产至少有 1 种规避措施生效
  3. 业务方补丁就绪后灰度部署，撤除临时规则 → 完成判据：临时规则台账清零

### WAF 性能优化——算法分层筛选与正则引擎选型

1. 设计流量筛选漏斗（IP 白名单 → URL 路径 → 方法 → 头部 → 最终正则） → 完成判据：每层过滤比例可量化
  2. 默认引擎选 RE2，对二进制场景（图片上传等）切 PCRE → 完成判据：规则级引擎配置
  3. 监控每层 CPU 开销，定位新瓶颈 → 完成判据：性能瓶颈定位表

### 提权行为检测规则——高权限子进程父进程低权限

1. 采集每个进程的 uid、pid、ppid → 完成判据：进程树+权限数据可用
  2. 部署规则：父进程 uid>0 且子进程 uid=0 → 告警 → 完成判据：规则上线
  3. 排查正常场景（如 sudo、setuid 程序）以去除误报 → 完成判据：白名单清单

### 反连木马检测规则——bash STDIN/STDOUT 绑定 socket

1. 采集每个 bash/sh 进程的 STDIN/STDOUT fd 信息 → 完成判据：fd 关联数据可用
  2. 部署规则：bash 的 STDIN 或 STDOUT 绑定 socket → 告警 → 完成判据：规则上线
  3. 对已知合法场景（如 ssh remote command）做白名单 → 完成判据：白名单清单
  4. 对复杂后门（mod_rootme 类）单独建模，基于"异常行为组合"而非单一特征 → 完成判据：复杂后门检测规则

### 多系统数据关联检测——NIDS 文件上传 + HIDS CGI 创建

1. NIDS 与 HIDS 时间戳同步，建立事件关联窗口 → 完成判据：跨系统时间对齐
  2. 部署规则：NIDS 文件上传事件 + HIDS CGI 创建事件（窗口 ≤ N 秒）→ 告警 → 完成判据：关联规则上线
  3. 对正常业务文件上传做基线白名单 → 完成判据：白名单清单

## B — 失效与边界 (Boundary)

- **Delphi 法四轮建立指标体系**：专家少于 10 人导致主观偏差大；问题数超过 25 个专家敷衍作答；跳过第三轮直接定稿，遗漏指标或保留了不适合的指标。
- **跨时间维度漏洞布防——临时规避措施**：干等补丁不作为，期间被 0day/1day 打穿；或 WAF 加规则过激误杀正常用户。
- **WAF 性能优化——算法分层筛选与正则引擎选型**：全流量直接进 PCRE——ModSecurity 历史上多次出现 DoS 漏洞；或全用 RE2 导致图片上传场景漏检。
- **提权行为检测规则——高权限子进程父进程低权限**：不做白名单——sudo、sshd 切换等正常行为大量误报；或数据采集频率过低，错过短时提权过程。
- **反连木马检测规则——bash STDIN/STDOUT 绑定 socket**：只检测简单反连，漏掉 mod_rootme 这类精巧后门；或规则过于宽泛，所有 bash + 网络都告警导致误报。
- **多系统数据关联检测——NIDS 文件上传 + HIDS CGI 创建**：时间不同步导致关联失效；或白名单不全导致大量误报。
