# 决策规则速查 — 应急响应与蓝队

| 能力 | 一句话规则 |
|---|---|
| 攻击者身份溯源 | 这个能力解决的问题是： 已有攻击者的某个锚点（一个 uid、一个域名、一封邮件、一次扫描连接），能不能收敛到"是谁" |
| 抑制与隔离决策 | 这个能力解决的问题是： 事件正在发生，必须立刻决定"断什么、不断什么、先救什么" |
| 蓝队基础能力建设与暴露面收敛 | 这个能力解决的问题是： 预算、人力、时间都有限，蓝队能力应该按什么顺序建，才不会建出一堆互不衔接的设备和规则 |
| 检测规则与日志管道工程 | 这个能力解决的问题是： 告警写了一堆，但要么不响，要么响得没人看 |
| 检测覆盖度与有效性验证 | 这个能力解决的问题是： "设备装了、规则写了、告警没响"，到底是没攻击，还是坏了 |
| 主机现场多线并行排查 | 这个能力解决的问题是： 拿到一台（或一批）可疑主机，不知道从哪查起，也不知道查到什么程度算查完 |
| 影响范围圈定与攻击链回溯 | 这个能力解决的问题是： 一台机器确认失陷后，"还有没有别的"和"从哪进来的"这两个问题都必须回答，否则清理等于没做 |
| 应急响应取证与处置顺序 | 这个能力解决的问题是： 事件已确认，但现场只有一次，而接下来每一个动作都会销毁一部分证据 |
| 应急工具链与样本快检 | 这个能力解决的问题是： 方法知道了，但手上该拿什么工具、以什么顺序跑、哪些参数会让证据消失 |
| 日志取证与完整性反推 | 这个能力解决的问题是： 攻击者会清日志，而"日志里没有可疑记录"到底是"没发生"还是"被删了"，必须能区分 |
| Windows 持久化点全量排查 | 这个能力解决的问题是： "重启之后木马又活了，但 Autoruns / 任务计划程序 / services.msc 里找不到 |
| 流量形状与隐蔽信道狩猎 | 这个能力解决的问题是： 流量全程加密、没有解密能力，甚至没有已知恶意 IOC，还能不能发现 C2 与外传 |
