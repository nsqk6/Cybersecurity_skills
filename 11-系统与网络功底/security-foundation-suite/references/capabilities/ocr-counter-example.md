## I — 方法论骨架 (Interpretation)

**宏展开导致递归爆炸** — C 语言宏按名称调用，每次出现参数都会重新求值。把递归函数改成宏时，递归调用会被展开两次以上，导致指数级增长。安全场景：任何"内联展开"优化都要警惕参数重复求值的副作用——这在模板、代码生成器、宏系统中普遍存在。

**未排序数组破坏二分查找** — 二分查找的前置条件是数组已排序，但调用方可能忘记排序。完整检查排序要 O(n) 次比较，代价高。若不检查，未排序数组会静默返回错误结果——这在安全场景下意味着认证判定可能错误。需要在成本和检测率间权衡。

**二分查找 90% 程序员写错** — 二分查找看似简单，但边界条件（空数组、单元素、目标不在数组中、范围收缩时的 off-by-one）极易出错。90% 的专业程序员在两小时内写出的版本有 bug；从算法发表到第一个正确实现花了 16 年。任何"这很简单"的代码都值得用验证技术严格检查。

**输入歧义导致命令执行（Quito 案例）** — 数据字段中的合法值（城市名 Quito）被解释为控制命令（quit），导致程序停止。这是经典的"数据与命令混淆"漏洞——与 SQL 注入、命令注入同源。安全工程师应识别任何"数据可能被当作命令"的边界。

**ICMP 重定向消息会自动改写主机路由表（高风险）** — ICMP 重定向是设计上"信任路由器告诉主机更好的路径"，主机收到后会自动把消息里的路由加进自己的路由表。攻击者只要能向目标主机发送一个伪造源 IP 为"默认网关"的 ICMP 重定向包，就能让目标主机的流量绕道经过攻击者控制的中间节点，从而实现 MITM。这是经典的"ICMP 重定向 MITM"基础。生产环境应在主机和路由器侧禁用接收/处理 ICMP 重定向。

**SNMP 安全演进——v1/v2c 无安全，v3 分离安全模块** — SNMP 是网络设备远程管理的事实标准。v1 完全无安全；v2c 仅"团体字"（community string）以明文传输，等价于密码明文——抓包即可窃取。攻击者获取 community string 即可读设备配置（MIB）、修改参数（SetRequest）、重启设备。v3 才引入 USM（用户安全模块，加密 + 认证）和 VACM（访问控制）。安全含义：(1) 网络中只要还有 v2c 设备，整个网管体系就可能被嗅探；(2) 必须用 ACL 限制 SNMP 仅允许网管站源 IP；(3) 发现默认 community string `public`/`private` 立即整改。

**RIP 路由协议的安全弱点与 RIP2 才有的密码认证** — RIP v1 把路由信息以广播（255.255.255.255）方式每 30 秒向全网发送，且无任何认证。这意味着：(1) 任何同网段主机都能伪造 RIP 响应，让路由器把流量引向攻击者控制的"下一跳"（路由欺骗/中间人）；(2) 广播方式也暴露网络拓扑给所有监听者。RIP2 改用多播并支持密码认证，但密码认证是明文还是加密取决于实现。安全含义：现代网络应优先选 OSPF（链路状态、支持强认证），仍用 RIP 的多是老设备或边缘网络，需特别做接入控制。

## E — 执行步骤 (Execution)

### ICMP 重定向消息会自动改写主机路由表（高风险）

1. 检查主机 `net.ipv4.conf.all.accept_redirects` 是否为 0 → 应为 0
  2. 在防火墙/IDS 上对 ICMP type 5 包告警 → 任何出现即异常
  3. 路由器侧关闭发送 ICMP 重定向 → 防止被滥用

### SNMP 安全演进——v1/v2c 无安全，v3 分离安全模块

1. 全网扫描 SNMP 服务（UDP 161） → 列出所有响应设备
  2. 检查每台设备 SNMP 版本 → v1/v2c 设备列入升级计划
  3. 检查 community string 是否为默认 `public`/`private` → 立即改为长随机串
  4. 在设备 ACL 上限制 SNMP 源 IP → 仅允许网管站
  5. 升级到 SNMPv3，配置 USM 用户加密 + 认证

### RIP 路由协议的安全弱点与 RIP2 才有的密码认证

1. 全网审计路由协议 → 仍用 RIP v1 的应立即升级或加 ACL
  2. 若必须用 RIP → 启用 RIP2 + 密码认证
  3. 在接入层阻止非路由器设备发送 RIP 包（端口 520 UDP） → 防止伪造
  4. 优先迁移到 OSPF/IS-IS → 链路状态型支持 MD5/SHA 认证

## B — 失效与边界 (Boundary)

- **宏展开导致递归爆炸**：宏参数被多次求值导致语义变化；递归宏导致指数爆炸；表面"加速"实则灾难性减速
- **未排序数组破坏二分查找**：信任调用方已排序→实际未排序→静默错误；完整检查太贵→被关闭；部分检查覆盖不全→漏检
- **二分查找 90% 程序员写错**：自信"能一次写对"；只测正常用例不测边界；用"看起来对"代替"证明对"
- **输入歧义导致命令执行（Quito 案例）**：数据字段值碰巧匹配命令关键字；没有区分数据通道和控制通道；错误处理只考虑已知命令而不考虑"数据碰巧是命令"
- **ICMP 重定向消息会自动改写主机路由表（高风险）**：仅在主机禁用而在路由器仍发送，仍可能被中间人伪造；忽略 ICMPv6 的对应消息（Router Redirect）
- **SNMP 安全演进——v1/v2c 无安全，v3 分离安全模块**：升级 v3 但仍保留 v2c 兼容（等于没升级）；ACL 写反导致外网仍能访问
- **RIP 路由协议的安全弱点与 RIP2 才有的密码认证**：启用密码认证但密码明文传输（部分老实现）；忽视接入层防护，攻击者仍可伪造 RIP
